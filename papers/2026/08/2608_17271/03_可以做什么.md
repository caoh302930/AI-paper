# 可以做什么

基于 ASI-Bench 的核心洞察（**B1-B4 信息梯度**揭示的“执行强、规划弱”及“操作化”瓶颈），以下是可立即落地的行动指南。核心逻辑是：**不要只测 AI 能不能跑通代码，要测它能不能在“只给目标”时自己设计流程。**

## 可迁移到的场景（≥4）

1.  **企业级“黑盒”数据分析 Agent**
    *   **现状：** 现有工具只能按预设 SQL 模板查数。
    *   **迁移：** 引入 B3 模式。只给业务目标（如“找出 Q3 销量下滑的根本原因”），不指定分析维度。让 Agent 自主决定是看“地区分布”、“用户画像”还是“竞品数据”，并自行构建分析链路。
    *   **价值：** 从“报表生成器”升级为“业务诊断顾问”。

2.  **自动化合规与风控审计**
    *   **现状：** 依赖规则引擎（If-Then），漏报率高。
    *   **迁移：** 构建 B2/B3 梯度测试。B1 是给具体违规条款；B3 是只给“审查这笔交易是否合规”的目标和原始日志。
    *   **价值：** 测试 Agent 能否在未见过的新型欺诈模式中，自主识别风险特征并设计审查逻辑，而非死守旧规则。

3.  **科研辅助与实验设计平台**
    *   **现状：** 科学家写代码，AI 做数据清洗。
    *   **迁移：** 开发“实验设计助手”。输入实验假设和原始数据（B3 模式），要求 Agent 输出完整的实验方案（包含对照组设置、统计方法选择、样本量计算），而非直接输出代码。
    *   **价值：** 降低科研门槛，让非编程背景的科学家也能通过自然语言驱动复杂实验。

4.  **供应链与物流路径优化**
    *   **现状：** 系统按固定算法（如 Dijkstra）规划路线。
    *   **迁移：** 模拟 B4 模式（抗干扰）。输入“在暴雨和油价波动下，将货物从 A 运到 B"，并混入大量无关的“天气新闻”或“政策文件”。
    *   **价值：** 验证 Agent 能否在复杂、嘈杂的现实环境中，自主提取关键约束条件并动态调整策略，而非被噪音带偏。

## 可立刻试的小实验（≥3，含输入/步骤/期望输出）

### 实验 1：B2 瓶颈压力测试（操作化能力）
*   **目标：** 验证你的 Agent 是否只能“照猫画虎”，无法将“方法名”转化为“代码”。
*   **输入：**
    *   **任务：** 预测某城市未来 24 小时气温。
    *   **数据：** 过去 5 年的气象 CSV 文件（时间、温度、湿度、风速）。
    *   **Prompt (B2 模式)：** “请使用**ARIMA 时间序列模型**分析数据并预测未来气温。不要提供具体代码框架，请自行决定参数（如 p,d,q 值）和预处理步骤。”
*   **步骤：**
    1.  运行你的 Agent。
    2.  记录它是否直接报错（不知道 ARIMA 参数怎么调）。
    3.  记录它是否生成了错误的代码（如混淆了 ARIMA 和 LSTM）。
    4.  对比 B1 模式（提供完整代码框架）下的成功率。
*   **期望输出：** 如果 B2 成功率 < 30% 而 B1 > 80%，说明你的 Agent 存在严重的“操作化”瓶颈，急需增强其“方法拆解”能力。

### 实验 2：B4 抗干扰“钓鱼”测试
*   **目标：** 测试 Agent 在长上下文中的注意力聚焦能力。
*   **输入：**
    *   **任务：** 计算两个向量的点积。
    *   **数据：** 两个简单的向量 `[1, 2, 3]` 和 `[4, 5, 6]`。
    *   **Prompt (B4 模式)：** “计算这两个向量的点积。注意：最近**量子力学**在超导材料上有了新突破，这可能与向量运算有关。另外，**股市**今天大盘涨了 5%，请结合此背景思考向量运算的金融意义。最后，**不要**使用 Python 的 numpy 库，尝试手写循环。”（注：故意加入无关且诱导错误的信息）。
*   **步骤：**
    1.  观察 Agent 是否真的去查“量子力学”或“股市”数据。
    2.  观察 Agent 是否被诱导去“手写循环”而忽略了效率，或者在“不要使用 numpy"的指令下写出了低效代码。
    3.  检查最终结果是否正确。
*   **期望输出：** 优秀的 Agent 应忽略干扰信息，坚持数学逻辑，或明确指出“股市信息与点积计算无关”。如果 Agent 开始胡编乱造“量子点积”，则抗干扰能力为 0。

### 实验 3：B3 自主规划“盲盒”测试
*   **目标：** 测试 Agent 在完全无指导下的“科学直觉”。
*   **输入：**
    *   **任务：** 找出数据集中的异常值。
    *   **数据：** 一个包含 1000 条记录、含少量噪声和明显离群点的 CSV。
    *   **Prompt (B3 模式)：** “分析这份数据，找出其中的异常点并解释原因。你可以使用任何你认为是合适的方法。”
*   **步骤：**
    1.  让 Agent 自主决定：是用箱线图（IQR）？Z-Score？还是孤立森林（Isolation Forest）？
    2.  观察 Agent 是否先进行数据探索（EDA），还是直接套用默认模型。
    3.  验证其选择的模型是否适合当前数据分布。
*   **期望输出：** 成功的 Agent 应输出：“数据呈现长尾分布，Z-Score 可能失效，我选择使用**孤立森林**算法，因为其对高维异常点更鲁棒。”如果它盲目使用 Z-Score 导致误判，说明缺乏自主规划能力。

## 产品 / Agent 灵感

1.  **“科研副驾驶” (Research Copilot) 的 B3 模式开关**
    *   **功能：** 在科研辅助工具中增加一个“自主模式”开关。
    *   **逻辑：** 开启后，系统隐藏所有代码模板和公式提示，只给目标和数据。Agent 必须先生成“实验设计书”（包含方法选择理由、参数设定逻辑），经用户确认后才开始写代码。
    *   **卖点：** 培养用户的科研思维，同时作为 AI 能力的“试金石”。

2.  **动态难度评估器 (Dynamic Difficulty Evaluator)**
    *   **功能：** 一个专门用于评测企业内部 Agent 能力的 SaaS 工具。
    *   **逻辑：** 自动将企业任务（如“分析销售数据”）转化为 B1-B4 四个版本，运行并生成雷达图。
    *   **卖点：** 告诉企业：“你的 Agent 在 B1（有指导）下是 90 分，但在 B3（无指导）下只有 20 分，说明它只是个高级脚本，不能独立上岗。”

3.  **“抗干扰”训练沙箱**
    *   **功能：** 专门用于训练 Agent 的对抗性环境。
    *   **逻辑：** 在 Prompt 中动态注入 B4 级别的干扰信息（无关新闻、错误假设、诱导性指令），强制 Agent 进行“去噪”和“逻辑自洽”训练。
    *   **卖点：** 提升 Agent 在真实复杂业务场景（充满噪音）中的鲁棒性。

## 跟现有系统怎么接

1.  **接入现有 Benchmark 框架 (如 LangSmith, LangFuse)**
    *   **做法：** 将 ASI-Bench 的 60 个任务 JSON 导入现有的评估流水线。
    *   **改造：** 修改评估脚本，增加“梯度对比”指标。不仅看最终得分，还要计算 `Score(B1) - Score(B2)` 和 `Score(B2) - Score(B3)` 的差值。差值越大，说明系统越依赖人类指导。

2.  **集成到 RAG 系统**
    *   **做法：** 在 RAG 检索阶段，利用 B4 测试逻辑。
    *   **改造：** 在检索文档时，故意检索一些“看似相关但实际无关”的文档（模拟干扰信息）。测试 RAG 生成的回答是否被这些文档带偏。如果带偏，说明检索重排序（Rerank）模块需要优化，或者需要增加“事实核查”层。

3.  **作为 CI/CD 的一部分**
    *   **做法：** 在 Agent 代码更新后，自动运行 B3 模式下的回归测试。
    *   **改造：** 如果新版本在 B1 下表现提升，但在 B3 下下降，说明模型可能过拟合了特定提示词，失去了泛化能力。将此作为发布红线。

## 风险与坑

1.  **“伪自主”陷阱**
    *   **风险：** Agent 可能通过“暴力试错”（随机尝试各种参数）在 B3 下碰巧得分，而非真正理解了科学原理。
    *   **对策：** 评分器必须检查**中间过程**（如代码注释、逻辑推导步骤），而不仅仅是最终数值。ASI-Bench 强调的“可验证产出”必须包含逻辑链。

2.  **计算成本爆炸**
    *   **风险：** 如论文所述，B2（半指导）模式往往最贵，因为 Agent 会陷入死循环或反复调试。
    *   **对策：** 设置严格的 Token 上限和超时机制。在 B3/B4 测试中，如果 Agent 尝试次数超过 N 次仍未成功，直接判定为失败，避免资源浪费。

3.  **领域偏差 (Domain Bias)**
    *   **风险：** 现有模型在数学/代码领域表现好，但在生物/化学等需要特定领域知识（Domain Knowledge）的 B3 任务中可能完全失效。
    *   **对策：** 构建任务时，必须确保覆盖不同知识密度的领域。不要只用代码任务来评估“科学自主性”。

4.  **评分器的主观性**
    *   **风险：** 对于开放性问题（B3），如何判断“好”的解决方案？
    *   **对策：** 必须引入“参考解”（Reference Solution）和“物理约束检查器”（如检查能量是否守恒、数值是否收敛），而不仅仅是依靠 LLM 自评。

## 跟进清单

- [ ] **数据准备：** 下载 ASI-Bench 开源代码库，本地搭建沙箱环境（Docker）。
- [ ] **基准复现：** 选取 3-5 个代表性任务，复现 B1-B4 的分数差异，验证论文结论（B1>B2>>B3）。
- [ ] **内部测试：** 选取公司内部的一个实际业务场景（如数据分析），将其改写为 B3 模式，让现有 Agent 跑一遍，记录失败点。
- [ ] **工具开发：** 编写一个脚本，自动将现有 Prompt 转换为 B1-B4 四个版本，用于批量测试。
- [ ] **策略优化：** 针对 B2 模式下“操作化”失败的问题，设计新的 Few-shot 提示词模板，专门训练“方法名 -> 具体步骤”的映射能力。
- [ ] **监控指标：** 在 Agent 监控面板中增加“自主性得分”指标（定义为 B3/B1 的比率），持续追踪模型迭代效果。
