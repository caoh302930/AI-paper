## TL;DR and contributions
本文提出了一种名为 **LLM-as-a-Verifier** 的通用验证框架，核心思想是将“验证”本身视为一个可扩展的计算维度。不同于传统方法让大模型输出离散的分数（如 1-5 分），该方法直接利用模型对评分 Token 的完整概率分布计算期望值，从而获得连续的细粒度奖励信号。通过扩展评分粒度、重复评估和标准分解三个维度，该方法在无需额外训练的情况下，显著提升了从多条候选轨迹中筛选正确答案的能力。

**Main contributions:**
- 提出基于概率期望的连续评分机制，利用 Logits 分布而非离散 Token 输出，大幅降低评分平局率。
- 定义了验证的三个可扩展维度：评分粒度（Granularity）、重复评估（Repeated Evaluation）和标准分解（Criteria Decomposition）。
- 设计了 **Probabilistic Pivot Tournament (PPT)** 算法，以 $O(Nk)$ 的复杂度高效地从 $N$ 个候选中选出最优解，解决了全排列比较的成本问题。
- 证明了细粒度验证信号可作为任务进度的代理指标，并作为稠密奖励信号显著提升强化学习（RL）的样本效率。

**Compared against:** 传统 LLM-as-a-Judge（离散评分）、训练过的奖励模型（如 RoboReward, Robometer）、V1 基准（Parallel Reasoners）。
**On datasets:** Terminal-Bench V2 (代码/终端), SWE-Bench Verified (GitHub 问题修复), RoboRewardBench (机器人轨迹), MedAgentBench (医疗代理)。
**Headline improvements:** 在 Terminal-Bench V2 上，Pass@1 从 83.1% 提升至 **86.5%**（Oracle 上限为 92.1%）；在 RoboRewardBench 上偏好准确率达到 **87.4%**，超越所有训练过的专用奖励模型。

## What matters, what doesn't

- **🎯 Core idea (read carefully):** 验证的“概率化”本质。理解为何直接取 Logits 分布的期望（Continuous Score）比取最大概率 Token（Discrete Score）更能区分相似轨迹，以及由此衍生的三个扩展维度（粒度、重复、分解）。
- **🔧 Useful in practice:** **Probabilistic Pivot Tournament (PPT)** 算法。这是工程落地的关键，它如何在有限的 Token 预算下，通过“环状初筛 + 枢轴对决”策略，以低成本选出最佳候选。
- **📎 Nice to know:** 验证信号作为任务进度（Progress Proxy）的监控应用，以及在强化学习中作为稠密奖励（Dense Reward）提升样本效率的具体实验设置。
- **⚠️ Deprecated / superseded:** 传统的“离散打分”LLM Judge 范式。本文指出其在复杂任务中平局率过高（~27%），已不足以支撑测试时扩展（Test-Time Scaling）。
- **🔕 Skippable:** 详细的附录数学推导（除非需要复现 PPT 的统计特性）、部分特定基准的次要消融实验细节。

## Context and prerequisites

要真正理解这篇论文，需要建立两个核心概念的心理模型：**测试时扩展（Test-Time Scaling）**与**验证的瓶颈**。

首先，**测试时扩展**是指不改变模型参数，而是通过在推理阶段生成多个候选答案（Multiple Trajectories）并从中挑选最佳者来提升性能。这就像让一个学生做同一道题 5 遍，然后挑出最好的一份。然而，这种策略的上限取决于“挑选者”（Verifier）的能力。如果挑选者无法区分“稍微好一点”和“完全正确”的答案，那么生成再多候选也是徒劳。目前的瓶颈在于，传统的验证方法（LLM-as-a-Judge）通常让模型输出一个离散的整数（如 1 到 5 分）。这种离散化导致大量信息丢失：模型内心可能觉得 A 方案有 99% 的概率是好的，B 方案有 98% 的概率是好的，但离散评分可能都把它们归为"5 分”，导致无法区分。

其次，**概率分布的利用**是本文的破局点。大语言模型在生成 Token 时，实际上是在计算词表中每个词的概率分布。传统方法只取概率最大的那个词（Argmax），而本文主张利用整个分布（Expectation over Logits）。想象一下，离散评分像是在用一把只有 5 个刻度的尺子去测量长度，而概率期望则是利用尺子上的所有微小刻度，甚至通过概率加权得到亚毫米级的精度。这种“连续评分”不仅消除了平局，还让验证过程本身可以像训练一样进行“扩展”：通过增加评分的精细度（更多刻度）、重复测量（多次读数取平均）或拆解测量标准（分别测长度、宽度、高度），来系统性地提升验证的准确性。

## Method

### The big picture (layman version)

想象你要从 10 份不同的代码解决方案中选出最好的一份。传统的做法是请一个专家（LLM）给每份代码打个 1 到 5 的整数分，然后选最高分。但这有个大问题：如果两份代码都很优秀，专家可能都打 5 分，你就无法区分谁更好了，这就是“平局”。

**LLM-as-a-Verifier** 的做法完全不同。它不让专家只说一个数字，而是让专家“思考”并给出一个概率分布：比如它认为方案 A 有 60% 的概率得 5 分，40% 的概率得 4 分；方案 B 有 90% 的概率得 5 分，10% 的概率得 4 分。通过计算这些概率的加权平均值，我们得到了一个连续的分数（比如 A 是 4.6，B 是 4.9）。这样，即使两者都很强，也能分出高下。

为了进一步确保选得准，文章提出了三个“放大镜”：
1. **更细的刻度**：把 1-5 分变成 1-20 分，让区分度更高。
2. **多次测量**：让专家看 8 次，取平均分，消除偶然看走眼的误差。
3. **拆解标准**：分别检查“功能对不对”、“格式对不对”、“有没有报错”，最后综合打分。

最后，为了在 10 份方案中快速找到最好的，文章设计了一个聪明的比赛规则（PPT）：先让所有人两两随机比一次，选出几个“种子选手”，然后只让剩下的选手和种子选手比，而不是让所有人互相比（那样太慢）。这样既省资源，又能精准锁定最优解。

### The walkthrough

**1. 动机：从离散到连续的跨越**
传统的 LLM Judge 将验证过程建模为生成一个离散 Token $v \in \{1, \dots, G\}$。形式上，奖励模型输出 $R_{\text{LM}}(x, \tau) = \phi(\arg\max_g p_\theta(v_g | x, \tau))$。这种方法的致命弱点是**信息坍缩**：模型内部对两个不同轨迹的置信度分布可能差异巨大，但 Argmax 操作将它们强行映射到同一个离散值，导致高平局率（Terminal-Bench 上高达 26.7%）。

**2. 核心机制：概率期望评分**
LLM-as-a-Verifier 摒弃了 Argmax，转而计算评分 Token 分布的期望值。
给定任务 $x$、轨迹 $\tau$ 和评分 Token 集合 $V_{\text{score}} = \{v_1, \dots, v_G\}$，奖励函数定义为：
$$ R(x, \tau) = \frac{1}{CK} \sum_{c=1}^{C} \sum_{k=1}^{K} \sum_{g=1}^{G} p_\theta(v_g \mid x, c, \tau) \, \phi(v_g) $$
其中：
- $C$ 是评价标准的数量（Criteria Decomposition）。
- $K$ 是重复评估的次数（Repeated Evaluation）。
- $G$ 是评分粒度的数量（Scoring Token Granularity）。
- $p_\theta(v_g \mid \dots)$ 是模型对第 $g$ 个评分 Token 的 Logit 概率。
- $\phi(v_g)$ 是将 Token 映射为标量值的函数（如 $v_1 \to 1, v_{20} \to 20$）。

这个公式的物理意义是：我们不再问“模型认为最好的分数是多少”，而是问“模型认为所有可能分数的加权平均是多少”。这保留了模型的不确定性信息，使得 $R(x, \tau)$ 成为一个连续值，从而能区分细微差别。

**3. 三个扩展维度（Scaling Axes）**
- **粒度扩展 ($G$)**：增加 $G$（如从 5 增加到 20），相当于增加了评分的分辨率。实验表明，随着 $G$ 增加，正确轨迹与错误轨迹之间的信噪比（SNR）提升，平局率降为 0。
- **重复评估 ($K$)**：对同一轨迹进行 $K$ 次独立评估并取平均。根据大数定律，这降低了单次评估的方差（Variance），使分数更稳定。
- **标准分解 ($C$)**：将复杂的“正确性”拆解为多个子标准（如：规格符合度、输出格式、错误信号）。这避免了单一 Prompt 中的认知偏差，通过集成学习（Ensemble）提升鲁棒性。

**4. 排序算法：Probabilistic Pivot Tournament (PPT)**
当有 $N$ 个候选轨迹时，两两比较需要 $O(N^2)$ 次验证，成本过高。PPT 算法通过以下三步将复杂度降至 $O(Nk)$（$k \ll N$）：
1. **环状初筛 (Ring Pass)**：构建一个随机哈密顿环，让每个候选在“左位”和“右位”各出现一次，与邻居比较。这消除了模型对 Prompt 中位置（A/B 位置偏好）的偏差。
2. **枢轴选择 (Pivot Selection)**：根据环状初筛的胜率，选出前 $k$ 名作为“枢轴”（Pivots）。
3. **枢轴对决 (Pivot Rounds)**：所有非枢轴只与这 $k$ 个枢轴比较，枢轴之间也互相比较。
最终，根据加权胜率 $w_i / c_i$ 选出最优解。这种策略将计算资源集中在最可能获胜的候选上，而非浪费在明显较差的候选上。

**5. 偏好建模**
利用 Bradley-Terry 模型将连续分数转化为成对偏好概率：
$$ P(\tau_i \succ \tau_j \mid x) = \frac{1}{1 + \exp(-(R(x, \tau_i) - R(x, \tau_j)))} $$
这为 PPT 算法提供了软性的比较依据，而非硬性的胜负。

## Challenges in the field — and what this work addresses

**挑战一：验证信号的粗糙性导致无法利用测试时扩展**
*为什么难*：在测试时扩展中，模型生成的多个候选往往非常相似（例如代码逻辑正确但变量名不同，或机器人轨迹都接近目标但路径微调不同）。传统的离散评分（1-5 分）无法捕捉这种细微差异，导致“平局”频发，系统无法做出有效选择，浪费了生成多个候选的计算成本。
*本文方案*：通过**概率期望评分**和**粒度扩展**，将离散的评分空间转化为连续空间。实验证明，将粒度从 5 提升到 20，信噪比（SNR）显著提升，彻底消除了平局，使得系统能够区分那些“几乎正确”的轨迹。

**挑战二：验证器的方差与偏差**
*为什么难*：LLM 作为验证器本身具有随机性（Temperature 采样或内部噪声），且单一 Prompt 容易受到特定措辞或任务特征的误导（Bias）。一次性的评估可能因为偶然的噪声而给出错误判断。
*本文方案*：引入**重复评估**（降低方差）和**标准分解**（降低偏差）。重复评估通过平均化消除了随机噪声；标准分解将复杂的判断拆解为多个独立的子任务，防止模型“抓大放小”或“以偏概全”，从而获得更校准（Calibrated）的分数。

**挑战三：候选池排序的高昂计算成本**
*为什么难*：为了从 $N$ 个候选中选出最好的，理论上需要进行 $N(N-1)/2$ 次两两比较。当 $N$ 较大（如 20 或 50）时，验证成本呈平方级增长，远超生成成本，使得该方法在实际应用中不可行。
*本文方案*：提出 **PPT 算法**。它不盲目地进行全排列比较，而是利用“环状初筛”快速筛选出有潜力的候选，并将剩余预算集中用于区分这些“热门选手”。实验显示，在 $N=20$ 时，PPT 仅需约 6000 次比较（$k=5$）即可达到接近全排列的准确率，而全排列需要 13000+ 次。

**本文未解决的问题**：
- **闭源模型的 Logits 访问**：该方法依赖访问模型的 Logits（概率分布）。对于完全封闭的 API（如某些商业模型），无法直接获取 Logits。虽然附录 B.6 提出了两阶段 workaround（用开放模型模拟），但这增加了延迟和复杂度，并非完美的通用解。
- **动态标准生成**：目前的 $C$ 个标准是人工设计的（如代码的规格、格式、错误）。如何自动学习或动态生成针对特定任务的分解标准，仍是未来方向。

## Experiments and results

论文在四个跨领域基准上进行了验证，结果显著：

1.  **Terminal-Bench V2 (代码/终端)**：
    - 基线 Pass@1 (GPT-5.5): 83.1%
    - Oracle Pass@5 (理论上限): 92.1%
    - **LLM-as-a-Verifier (Ours): 86.5%**
    - *分析*：成功回收了约 3.4% 的 Oracle 空间，超越了所有 SOTA 基线（如 Claude Mythos + Terminus-2 的 82.0%）。

2.  **SWE-Bench Verified (真实 GitHub 问题)**：
    - 混合候选池 Pass@1: 76.1%
    - Oracle Pass@3: 84.4%
    - **LLM-as-a-Verifier (Ours): 78.2%**
    - *分析*：在异构候选（来自不同模型）中表现优异，证明了验证器的泛化能力。

3.  **RoboRewardBench (机器人)**：
    - 训练过的专用模型 (RoboReward-8B): 81.4%
    - **LLM-as-a-Verifier (Ours): 87.4%**
    - *分析*：零样本（Zero-shot）方法超越了需要大量数据训练的专用奖励模型，且与人类标注的 MAE 从 1.11 降至 0.72。

4.  **MedAgentBench (医疗)**：
    - 基线 Pass@1: 70.2%
    - **LLM-as-a-Verifier (Ours): 73.3%**
    - *分析*：在高风险、难验证的医疗领域同样有效。

**关键消融实验**：
- **粒度 ($G$)**：$G=1$ (离散) 时验证准确率 73.1%，$G=20$ 时提升至 77.5%。
- **重复 ($K$)**：$K=1$ 时 74.7%，$K=16$ 时 77.4%。
- **平局率**：离散评分在 $K=1$ 时平局率高达 26.7%，而连续评分始终为 0。

## Open questions and limitations

1.  **闭源模型的适配成本**：对于无法获取 Logits 的模型，两阶段 workaround（用开放模型模拟闭源模型的推理）是否引入了额外的误差或延迟？这在工业界大规模应用时可能成为瓶颈。
2.  **计算预算的权衡**：虽然 PPT 降低了复杂度，但 $O(Nk)$ 在 $N$ 很大时依然昂贵。是否存在自适应策略，根据任务的难度动态调整 $N, K, G$？
3.  **多轮交互的验证**：目前实验主要集中在单轮或短轨迹。在长程多轮对话或复杂规划中，验证器如何累积错误？如何避免“早期错误导致后续评分全面崩盘”？
4.  **标准分解的自动化**：目前依赖人工定义 $C$ 个标准。如果任务领域变化（如从代码变为法律），如何自动适应新的分解标准？
