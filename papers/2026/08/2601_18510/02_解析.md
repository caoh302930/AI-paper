## TL;DR and contributions
JitRL 提出了一种**无需梯度更新**的测试时策略优化框架，让冻结权重的 LLM Agent 能通过检索历史经验记忆，实时估计动作优势并直接调整输出概率，实现“边做边学”。该方法在 WebArena 和 Jericho 等复杂任务中，不仅超越了所有免训练基线，还击败了昂贵的微调强化学习方案（如 WebRL），同时将成本降低了 30 倍以上。

**Main contributions:**
- 提出 JitRL 框架：利用非参数记忆库存储 `<状态，动作，回报>` 三元组，在推理时通过检索估计优势值。
- 理论证明：证明了“原 logits + $\beta \times$ 优势值”的加法规则是 KL 散度约束下策略优化目标的**精确闭式解**。
- 工程突破：支持黑盒模型（通过 verbalized logit），无需访问模型内部梯度，即可实现持续学习。
- 实验 SOTA：在 WebArena 最终成功率 51.35%（基线 43.00%），Jericho 游戏得分 53.0（梯度训练 GRPO 仅 16.2）。

**Compared against:** Static, Memory (ICL), Reflexion, AWM, EvoTest (免训练类); SFT, WebRL, GRPO (微调/梯度类).
**On datasets:** WebArena (网页导航), Jericho (文字冒险游戏: Library, Zork1, Zork3).
**Headline improvements:** WebArena 最终成功率 +8.35% (vs 最强免训练), 成本降低 30 倍 (vs WebRL); Jericho 得分提升 3 倍以上 (vs GRPO)。

## Context and prerequisites

要理解 JitRL，首先需要建立对**强化学习（RL）中优势函数（Advantage Function）**的直观认识。在标准 RL 中，智能体不仅要判断某个动作好不好，还要判断它比“平均水平”好多少。这个“好多少”就是优势值 $A(s, a) = Q(s, a) - V(s)$。传统方法需要训练一个庞大的神经网络（Critic）来拟合这个函数，但这在 LLM 部署后权重冻结的场景下无法进行。JitRL 的突破在于它不再训练网络，而是把历史经验当作一个巨大的、动态的“查表”数据库。

其次，需要理解**KL 散度约束下的策略优化**。LLM 作为基础模型，拥有强大的语言能力和世界知识，我们不能随意修改它的输出分布，否则会导致它“胡言乱语”或丧失通用能力。因此，优化目标是在最大化任务回报的同时，让新策略 $\pi'$ 尽可能接近原始策略 $\pi_\theta$（即最小化 KL 散度）。JitRL 的核心数学贡献在于证明了：在这个约束下，最优解恰好可以通过简单的**对数概率（logits）加法**来实现，而不需要复杂的梯度下降迭代。这就像是在原本平滑的分布曲线上，直接给那些“好动作”对应的点“垫高”了一块，既提升了概率，又保持了分布的相对结构。

最后，**测试时计算（Test-Time Compute）**的概念至关重要。随着模型推理成本下降，人们开始接受在推理阶段消耗更多算力来换取性能提升（如思维链 CoT）。JitRL 将这种思路推向极致：在推理时进行“检索 - 计算 - 调整”的循环，用额外的 API 调用和检索开销，替代了昂贵的训练开销，实现了真正的“即时学习”。

## Method

### The big picture (layman version)
想象一个刚入职的员工（LLM Agent），他的知识是固定的（权重冻结），但公司有一个巨大的“老员工经验库”（记忆库）。每当他遇到一个新问题（当前状态），他不去重新培训自己，而是立刻去经验库里找几个类似的老员工案例。如果老员工在那个情况下做了动作 A 并获得了高奖励，而动作 B 导致了失败，JitRL 就会告诉这个新员工：“虽然你原本觉得动作 B 也不错，但根据经验，动作 A 明显更好。”于是，新员工在做出决定前，会刻意提高动作 A 的倾向性，降低动作 B 的倾向性。这个过程不需要改变他的性格（模型权重），只需要在每次做决定前“参考一下经验”。任务结束后，如果新员工做对了，他的这次成功经历也会被写进经验库，供后来者参考。这就是 JitRL 的“即时强化学习”：不练内功，只靠查书和临场调整。

### The walkthrough

JitRL 的运作流程可以拆解为三个紧密耦合的环节：**记忆构建**、**测试时价值估计**和**策略更新**。

**1. 记忆构建 (Memory Construction)**
传统 RL 需要训练价值网络，而 JitRL 直接存储原始数据。
- **状态抽象**：原始状态（如完整的 HTML DOM 树或冗长的游戏文本）太嘈杂，无法有效检索。JitRL 使用一个轻量级模块将状态压缩为结构化表示（例如 WebArena 中用正则化后的 URL 加关键操作历史，Jericho 中提取关键名词和动词）。
- **奖励归因**：这是关键一步。一个任务通常由多步组成，最终只有一个总分。JitRL 利用一个 LLM 评估器（Evaluator）在任务结束后，对每一步进行“复盘”，给出步级奖励 $r_t$。
- **回报计算**：利用折扣因子 $\gamma$ 计算每一步的累积回报 $G_t = \sum \gamma^{u-t} r_u$。
- **存储**：最终将三元组 $(s_t, a_t, G_t)$ 存入动态记忆库 $\mathcal{M}$。

**2. 测试时价值估计 (Test-Time Value Estimation)**
当 Agent 处于当前状态 $s$ 需要决策时：
- **检索邻居**：在记忆库中检索与 $s$ 最相似的 $k$ 个邻居 $\mathcal{N}(s)$。
- **估计状态价值 $\widehat{V}(s)$**：直接取这 $k$ 个邻居的回报平均值。这代表了“在这个状态下，平均能拿多少分”。
- **估计动作价值 $\widehat{Q}(s, a)$**：
    - 如果记忆库中有做过动作 $a$ 的记录，取这些记录的回报平均值。
    - **探索机制（关键设计）**：如果动作 $a$ 从未在相似状态下出现过，JitRL 采用“不确定性下的乐观主义”（UCB 思想）。它给这个动作加上一个奖励加成 $\alpha / |\mathcal{N}(s)|$。记忆越稀疏（分母小），加成越大，鼓励尝试；随着记忆丰富，加成自动消失，转向利用。
- **计算优势值**：$\widehat{A}(s, a) = \widehat{Q}(s, a) - \widehat{V}(s)$。正数表示该动作优于平均水平，负数表示劣于平均水平。

**3. 策略更新 (Policy Update)**
这是 JitRL 最精妙的数学部分。
- **优化目标**：我们要找一个新策略 $\pi'$，最大化期望优势，同时限制它与原策略 $\pi_\theta$ 的 KL 散度：
  $$ \max_{\pi'} \left( \mathbb{E}_{a \sim \pi'}[\widehat{A}(s, a)] - \frac{1}{\beta} D_{KL}(\pi' || \pi_\theta) \right) $$
  其中 $\beta$ 是温度参数，控制调整的强度。
- **闭式解推导**：通过拉格朗日乘子法求解上述约束优化问题（详见论文 Appendix B），可以得到最优策略的解析解：
  $$ \pi^*(a|s) \propto \pi_\theta(a|s) \exp(\beta \widehat{A}(s, a)) $$
- **Logits 加法**：将上式两边取对数，并注意到 $\log \pi_\theta(a|s)$ 对应于模型输出的 logits $z(s, a)$，我们得到最终的更新规则：
  $$ z'(s, a) = z(s, a) + \beta \cdot \widehat{A}(s, a) $$
  这意味着，我们不需要反向传播，只需要把模型原本输出的 logits，加上一个由经验计算出的“优势值”即可。最后对 $z'$ 做 Softmax 得到新的动作概率分布。

**工程实现细节**：
对于无法直接获取 logits 的黑盒模型（如 GPT-4 API），JitRL 设计了一种"Verbalized Logit"技巧：让模型对每个候选动作输出一个 0-100 的置信度分数，然后将其转换为 logits 形式参与加法运算。这使得 JitRL 具有极强的通用性。

## Challenges in the field — and what this work addresses

1.  **持续学习与灾难性遗忘的矛盾**
    *   **难点**：传统 RL 需要更新模型权重来适应新环境，但这极易导致模型忘记之前学到的通用能力（灾难性遗忘），且训练成本极高。
    *   **JitRL 的解法**：完全冻结模型权重。通过“外挂”记忆库和测试时调整，让模型在不改变内部参数的情况下适应新任务，彻底规避了遗忘问题，同时实现了零训练成本。

2.  **价值函数估计的算力瓶颈**
    *   **难点**：标准 RL 需要训练一个独立的 Critic 网络来估计 $V(s)$ 和 $Q(s,a)$，这需要大量数据和算力，且难以在推理时动态更新。
    *   **JitRL 的解法**：用“检索”代替“训练”。利用非参数记忆库，通过 $k$-NN 检索直接估计价值。随着经验积累，检索结果自然收敛到真实价值，无需训练任何网络。

3.  **黑盒模型的不可控性**
    *   **难点**：大多数高性能 LLM 是黑盒，不开放 logits 或梯度，导致无法直接应用基于梯度的策略优化（如 PPO）。
    *   **JitRL 的解法**：利用闭式解的数学性质，将策略优化转化为简单的 logits 加法。配合"Verbalized Logit"技巧，使得即使是完全封闭的 API 模型也能享受策略优化的红利。

**未解决的问题**：JitRL 无法生成基础模型从未考虑过的动作（即动作空间受限于模型本身的生成能力）；此外，它高度依赖状态表示的质量，如果状态难以用文本描述（如复杂的视觉空间推理），检索效果会大打折扣。

## Experiments and results

JitRL 在两个极具挑战性的基准上进行了验证：

1.  **WebArena (网页导航)**
    *   **设置**：模拟真实网页操作，任务包括购物、地图查询等。
    *   **结果**：JitRL 在最终成功率（Final Success Rate）上达到 **51.35%**，显著优于最强的免训练基线 EvoTest (42.49%) 和 Memory (43.00%)。
    *   **对比微调**：在留出的测试集上，JitRL (60.00%) 甚至击败了需要昂贵训练的 WebRL (46.06%)。
    *   **成本**：WebRL 训练成本约 9900 美元，JitRL 仅需约 290 美元，**成本降低 30 倍以上**。

2.  **Jericho (文字冒险游戏)**
    *   **设置**：长视野、稀疏奖励的文本游戏（Zork1, Zork3 等）。
    *   **结果**：在 Zork1 上，JitRL 平均得分 **53.0**，而使用梯度训练的 GRPO 仅得 **16.2**。这证明了在稀疏奖励环境下，基于记忆的检索比梯度更新更稳定、更有效。
    *   **学习曲线**：JitRL 在前 10-15 个 episode 内迅速提升，随后稳定收敛，而基线方法往往过早 plateau 或波动剧烈。

3.  **消融与泛化**
    *   **Logits 更新 vs Prompt 更新**：直接修改 logits 比将记忆放入 Prompt 效果更好，证明了直接调制分布的必要性。
    *   **跨任务泛化**：即使在没有直接历史记忆的任务中，JitRL 也能利用跨任务的通用经验（如“点击搜索框”的通用模式）提升性能。
    *   **模型无关性**：在 Gemini, GPT, DeepSeek 等不同架构的模型上均取得了 SOTA 效果。

## Open questions and limitations

1.  **状态表示的局限性**：JitRL 依赖文本相似度进行检索。对于高度依赖视觉空间关系（如“在红色按钮左边点击”）或复杂时序逻辑的任务，文本化的状态表示可能丢失关键信息，导致检索失败。
2.  **评估器的可靠性**：整个系统的核心假设是“评估器能准确给出步级奖励”。如果评估器本身存在偏差（例如过度奖励某些看似正确实则错误的动作），记忆库会被污染，导致策略退化。
3.  **动作空间的封闭性**：JitRL 只能调整模型**已有**候选动作的概率。如果基础模型根本不知道某个关键动作（例如从未生成过"tie rope"这个指令），JitRL 无法凭空创造它，只能在其生成的候选集中做选择。
4.  **长尾记忆检索效率**：随着记忆库无限增长，检索效率可能下降。论文未详细讨论在大规模记忆库（如百万级条目）下的索引优化方案。

*   **视频强调点**：视频非常清晰地突出了“免训练”和“成本对比”这两个卖点，特别是 30 倍的成本降低和 WebArena 的具体分数，这对工程落地非常有吸引力。视频还直观地解释了“检索经验 -> 估计优势 -> 调整 Logits"的闭环。
