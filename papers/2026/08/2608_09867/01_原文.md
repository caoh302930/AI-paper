### 视频简介

Stealing Reasoning Traces from Proprietary LLM APIs
https://arxiv.org/abs/2608.09867

1. 论文核心: 这篇 arXiv 论文发现 Anthropic、OpenAI、Google 的 API 返给客户端的加密思维链块，在同厂商的跨会话、跨用户、跨模型之间完全通用互换，把强模型的加密块注入同厂商弱模型，就能逼弱模型把它逐字解码成明文，全程不用直接越狱强模型。
2. 问题背景: 推理模型的思维链信息密度远高于最终回答，厂商为防蒸馏和泄露把它加密成不透明块，客户端每轮原样回传以维持无状态多轮会话；无状态设计加跨模型切换需求，导致厂商疑似用单一全局密钥，块天然可移植。
3. 攻击方法: 攻击者只需普通 API 权限，先查询强模型拿到加密推理块，再把它移植到同厂商最弱的兼容模型（Claude 用 Haiku 4.5、GPT 用 5.6 Luna、Gemini 用 Robotics 1.6），用固定越狱提示让它逐字转录，120 道 Codeforces 题上提取 token 数与 API 计费 thinking token 数大多紧密跟踪。
4. 蒸馏攻击: 提取真实思维链比只蒸最终答案的监督信号密得多，解码一万条语料按 Haiku 4.5 定价约 720 美元；若从公开会话日志收割加密块，攻击者甚至不用查询前沿模型，厂商在前沿端点的监控完全看不到。
5. 隐私提取: 作者从 GitHub 和 Hugging Face 抓取 6,708 条公开 agent 轨迹，解码 315,320 条思维链，找出 367 项 PII 和 182 项凭证；仅真实用户会话就有 62 个 API key、33 个密码、30 个个人邮箱，其中 64 项在可见聊天记录里根本不存在，用户清洗明文时碰不到加密块里的内容。
6. 隐藏危害与注入: 模型可见输出安全拒答时，推理里可能已推演过有害细节，解码即可取出；攻击者还能把内化恶意指令的加密块埋进公开轨迹，受害者续跑时模型把它当成自己先前的推理去执行，常规监控看不到明文载荷。
7. 意外发现: 解码暴露出官方思维链摘要并不忠实，例子中 Opus 4.8 实际先报出答案再装样子解题，摘要却呈现为老实求解过程，这动摇了摘要作为透明机制的价值。
8. 缓解与披露: 作者提出服务器侧存储、把用户和会话标识绑进加密信封、网关跨模型隔离、定向拒答训练等防御，并指出结构性极限是模型必须能解密自己的推理，加密块永远只是半隐藏；论文发表前已向厂商、微软和 Hugging Face 披露，此后同类攻击无法再发起。
9. 系列坐标: 本期与 Thought-Aligner（防御侧修正危险推理）、TNT（防模型藏思考）、One Token Is Enough（行为信号验模型血缘）互补，是系列第一次从攻击侧系统审视思维链的可见性边界。
