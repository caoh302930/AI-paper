# 可以做什么

基于 Ctx2Skill 论文的核心逻辑（零标注自博弈 + 跨时间回放），以下是可立即落地的执行方案。核心思路是：**将“长文档阅读”转化为“技能包生成”，利用模型自我对抗来提炼规则，而非直接依赖模型一次性推理。**

## 可迁移到的场景（≥4）

1.  **企业级合规与审计助手**
    *   **痛点：** 员工需阅读数百页的《合规手册》或《安全规范》才能回答具体业务问题，直接 RAG 常因规则隐含而遗漏关键约束。
    *   **应用：** 输入合规文档，运行 Ctx2Skill 生成“合规检查技能包”（如：*“若涉及跨境数据，必须检查字段 X 和 Y，否则违规”*）。后续审计 Agent 直接加载该技能包，无需反复阅读原文，准确率显著提升。

2.  **复杂 SaaS/工业软件操作向导**
    *   **痛点：** 软件操作手册冗长，用户遇到“报错 A 导致流程 B 中断”时，直接搜索文档难以定位隐含的因果链条。
    *   **应用：** 将操作手册作为 Context，让模型自博弈生成“故障排查技能树”。生成的技能可嵌入客服 Agent，使其能像老员工一样，根据隐含规则快速给出排错步骤，而非机械检索。

3.  **法律/医疗病历结构化分析**
    *   **痛点：** 法律判决书或病历中存在大量非标准化的隐含逻辑（如：*“若症状 X 且无药物 Y，则判定为 Z"*），传统关键词匹配失效。
    *   **应用：** 输入历史判例或临床指南，通过自博弈提炼“判例推理规则”或“诊断逻辑链”。生成的技能可作为 System Prompt 注入分析模型，辅助律师或医生进行初步逻辑推演。

4.  **动态政策/新闻情报研判**
    *   **痛点：** 政策文件频繁更新，且不同条款间存在互斥或依赖关系，人工总结滞后且易出错。
    *   **应用：** 针对新发布的政策文档，快速运行 Ctx2Skill 生成“政策执行约束集”。情报 Agent 加载该技能集后，能自动识别新业务场景下的合规风险点，实现“文档即代码”的即时响应。

## 可立刻试的小实验（≥3，含输入/步骤/期望输出）

### 实验 1：单文档“找茬”技能生成（验证自博弈有效性）
*   **输入：** 一份 5-10 页的虚构《公司报销制度》PDF（包含 3-5 个容易混淆的隐性规则，如“出差超过 3 天需附行程单，但 3 天整不需要”）。
*   **步骤：**
    1.  **初始化：** 设定 Reasoner 为 GPT-4o，Challenger 为 GPT-4o，Judge 为 GPT-4o。
    2.  **第 1 轮：** Challenger 根据文档生成 5 个报销场景题（含陷阱）。
    3.  **推理与判分：** Reasoner 尝试回答，Judge 对照文档规则判分。
    4.  **失败驱动：** 收集 Reasoner 答错的案例，让 Proposer 分析“为什么错”，Generator 生成一条修正后的 Markdown 技能（如：*“注意：天数计算包含起止日，3 天整不属于‘超过 3 天’”*）。
    5.  **迭代：** 重复 3 轮，观察技能集变化。
*   **期望输出：** 最终生成一个包含 3-5 条精炼规则的 `skills.md`。对比直接 Prompt“请总结报销规则”，检查生成的技能是否覆盖了那些“容易混淆”的隐性陷阱。

### 实验 2：跨模型技能迁移（验证技能通用性）
*   **输入：** 同一份《报销制度》文档。
*   **步骤：**
    1.  **强模型训练：** 使用 GPT-4o 运行上述实验，生成最终技能集 $\mathcal{S}_{strong}$。
    2.  **弱模型测试 A：** 将 $\mathcal{S}_{strong}$ 作为 System Prompt 输入给 GPT-3.5-turbo（或开源小模型如 Qwen-7B），测试其回答新报销问题的能力。
    3.  **弱模型测试 B：** 让 GPT-3.5 直接阅读文档（无技能包）回答同样问题。
    4.  **对比：** 记录两者的准确率。
*   **期望输出：** 弱模型在加载强模型生成的技能后，准确率应显著高于直接阅读文档（预期提升 10%-20%），证明技能具有“知识蒸馏”和“跨模型迁移”价值。

### 实验 3：对抗崩溃检测（验证 Cross-Time Replay 必要性）
*   **输入：** 一份复杂的《API 接口文档》（包含大量参数依赖）。
*   **步骤：**
    1.  **无回放组：** 运行 5 轮自博弈，直接取第 5 轮的技能集 $\mathcal{S}_{final}$。
    2.  **有回放组：** 运行 5 轮，但在每轮收集“简单题”和“难题”探针，最后用 Cross-Time Replay 算法选出最优轮次的技能集 $\mathcal{S}_{opt}$。
    3.  **测试：** 用两组技能集分别回答 20 道新题目（包含简单基础题和复杂组合题）。
*   **期望输出：** 无回放组可能在“难题”上得分高，但在“简单题”上出现严重退化（过拟合）；有回放组在两类题目上的综合得分（乘积）应更高，技能更均衡。

## 产品 / Agent 灵感

1.  **“文档预处理器”中间件 (Doc2Skill Engine)**
    *   **定位：** 一个独立的 SaaS 服务，位于 RAG 系统之前。
    *   **功能：** 用户上传 PDF/Word，系统后台自动运行 Ctx2Skill，输出 `skills.json` 和 `context_summary.md`。
    *   **价值：** 下游 Agent 只需加载轻量级的技能包，无需加载几百页原文，大幅降低 Token 消耗，提升推理速度和准确率。

2.  **自适应合规审计 Agent**
    *   **定位：** 金融/医疗行业的合规审查工具。
    *   **功能：** 每次政策更新时，自动触发 Ctx2Skill 流程，生成“新规则差异包”。审计 Agent 自动将新旧技能合并，实时扫描历史业务数据，标记出因新规则而产生的潜在违规。
    *   **亮点：** 解决“政策更新后，旧模型不知道新规则”的滞后问题。

3.  **游戏/模拟环境 NPC 进化系统**
    *   **定位：** 游戏开发工具链。
    *   **功能：** 将游戏设定文档（世界观、物理规则、任务逻辑）作为 Context，让 NPC 通过自博弈生成“行为技能树”。
    *   **价值：** NPC 不再依赖硬编码，而是根据文档动态进化出符合设定的复杂行为策略，且能自我修正逻辑漏洞。

## 跟现有系统怎么接

1.  **接入 RAG 管道 (LangChain/LlamaIndex)**
    *   **替换节点：** 将传统的 `VectorStore` 检索节点，替换为 `Ctx2Skill` 生成的 `System Prompt` 注入节点。
    *   **流程：** `上传文档` -> `Ctx2Skill 离线运行 (生成技能)` -> `技能存入知识库` -> `用户提问` -> `检索技能 + 少量原文片段` -> `LLM 推理`。
    *   **优势：** 减少检索噪音，直接注入结构化逻辑。

2.  **接入 Agent 编排框架 (AutoGen/CrewAI)**
    *   **角色映射：** 将 Ctx2Skill 中的 5 个角色直接映射为 AutoGen 的 Agent 角色。
    *   **配置：**
        *   `Challenger` = `TaskGeneratorAgent`
        *   `Reasoner` = `SolverAgent`
        *   `Judge` = `ValidatorAgent`
        *   `Proposer/Generator` = `RefinerAgent`
    *   **逻辑：** 编写一个 `SelfPlayOrchestrator` 脚本，控制这 5 个 Agent 的循环对话，直到收敛，输出最终技能文件。

3.  **接入微调数据流水线**
    *   **用途：** 将 Ctx2Skill 生成的 `失败案例 + 修正技能` 作为高质量的 Instruction Tuning 数据。
    *   **操作：** 收集自博弈过程中的 `(Context, Task, Failure_Analysis, New_Skill)` 四元组，用于微调垂直领域的小模型，使其具备更强的规则内化能力。

## 风险与坑

1.  **LLM-as-a-Judge 的幻觉放大**
    *   **风险：** 如果 Judge 模型本身对文档理解有误，会错误地判定 Reasoner 的正确答案为“失败”，导致技能集向错误方向进化（奖励黑客）。
    *   **对策：** 引入“多裁判投票机制”（3 个不同模型或同一模型不同温度采样），只有 majority 判定失败才触发技能更新；或定期用少量人工标注的“黄金测试集”校准 Judge。

2.  **计算成本爆炸**
    *   **风险：** 5 轮自博弈 x 5 个角色 x 多轮对话 = 极高的 Token 消耗和延迟。
    *   **对策：**
        *   **早停机制：** 设定收敛阈值，若连续两轮技能集无实质性更新（Jaccard 相似度>0.95），立即停止。
        *   **模型降级：** Challenger/Reasoner 用大模型，Proposer/Generator 用中等模型，Judge 用专用小模型（若领域特定）。

3.  **技能集臃肿 (Skill Bloat)**
    *   **风险：** 随着迭代，生成的技能可能包含大量冗余或冲突的规则，导致 Prompt 过长，超出上下文窗口或干扰推理。
    *   **对策：** 在 Generator 阶段强制要求“去重”和“合并”；在 Cross-Time Replay 阶段，不仅选准确率，还要选“技能集长度最短且有效”的轮次。

4.  **静态文档的局限**
    *   **风险：** 论文针对静态文档。若文档是动态流（如实时新闻），自博弈无法实时跟进。
    *   **对策：** 采用“增量更新”策略，仅对文档变更部分运行局部自博弈，而非全量重跑。

## 跟进清单

- [ ] **环境搭建：** 准备 AutoGen 或 LangGraph 框架，配置 5 个角色的 Prompt 模板（参考论文附录 B）。
- [ ] **数据准备：** 选取 1 个真实业务场景的长文档（如 50 页+），并人工构造 20 个“陷阱题”作为验证集（Ground Truth）。
- [ ] **原型开发：** 实现单轮自博弈循环（Challenger -> Reasoner -> Judge -> Update），跑通最小闭环。
- [ ] **机制验证：** 加入 Cross-Time Replay 逻辑，对比“直接取最后一轮”与“回放选择”的效果差异。
- [ ] **成本评估：** 记录单次完整流程的 Token 消耗和耗时，计算 ROI（提升的准确率 vs 增加的成本）。
- [ ] **迁移测试：** 尝试将生成的技能包迁移到开源小模型（如 Llama-3-8B），验证通用性。
- [ ] **文档输出：** 编写内部技术文档，定义“技能格式标准”（Markdown Schema），以便下游系统调用。
