# 可以做什么

基于 IceBreaker 论文的核心逻辑（**共振感知兴趣蒸馏 + 交互导向列表生成 + 混合奖励搜索**），以下是可立即落地的执行方案。核心思路是：**不要等用户提问，先帮用户“想”出他们真正想聊的话题，并以列表形式呈现。**

## 可迁移到的场景（≥4）

1.  **智能客服/售后助手（冷启动转化）**
    *   **痛点**：用户进线后只说“你好”或沉默，客服机器人回复“请问有什么可以帮您”导致用户流失。
    *   **应用**：利用用户**历史订单/浏览记录**作为“历史会话摘要”，通过 RID 模块识别用户最可能关心的售后点（如：刚买的手机是否还在保修期、上次退货的进度），生成 3 个针对性问题（如：“您上周购买的耳机还在保修期内，需要查询吗？”），而非通用问候。

2.  **教育/语言学习陪练（保持学习动力）**
    *   **痛点**：学生打开学习 App 后不知道练什么，容易放弃。
    *   **应用**：分析用户**错题本/历史练习记录**，识别“薄弱但感兴趣”的知识点（如：用户多次练习“虚拟语气”但正确率低，且曾浏览过相关电影）。生成开场列表：“我们要不要聊聊《泰坦尼克号》里的虚拟语气用法？”、“来挑战 3 道虚拟语气高频错题？”、“用虚拟语气描述你现在的梦想”。

3.  **心理健康/情感陪伴 Bot（建立信任）**
    *   **痛点**：用户情绪低落时，AI 的“今天过得怎么样”显得敷衍，用户不愿开口。
    *   **应用**：基于用户**过往倾诉记录**（脱敏后），识别“高频情绪触发点”（如：工作压力、家庭关系）。生成共情式开场：“上次提到项目截止日期的压力，这周有好转吗？”、“如果现在可以给自己放个假，你最想做什么？”。

4.  **电商导购/内容推荐 Agent（提升点击率）**
    *   **痛点**：用户进入直播间或商品页，缺乏明确购买意图，浏览即走。
    *   **应用**：结合**浏览轨迹 + 收藏列表**，识别“高意向但未决策”的商品。生成引导列表：“这款运动鞋的配色您收藏了，需要看真人试穿视频吗？”、“您关注的这款相机，最近有针对新手的配件礼包，要看看吗？”。

## 可立刻试的小实验（≥3）

### 实验 1：构建“兴趣重访”代理信号（RID 简化版）
*   **输入**：用户过去 5 次对话的摘要文本（JSON 格式）。
*   **步骤**：
    1.  使用 LLM（如 Qwen2.5-7B）提取每次对话的核心 Topic（如：动漫、编程、健身）。
    2.  编写 Prompt 判断：Topic A 和 Topic B 是否属于同一兴趣领域？（例如：“《海贼王》”和“动漫展”是同一领域）。
    3.  统计每个 Topic 的“重访次数”（即用户是否在不同时间多次提及）。
    4.  筛选出重访次数≥2 的 Topic 作为“高共鸣兴趣”。
*   **期望输出**：一个 JSON 列表 `{"high_resonance_topics": ["动漫", "Python 编程"]}`。
*   **验证**：人工检查这些 Topic 是否真的符合该用户画像（对比用户画像标签）。

### 实验 2：混合奖励列表搜索（简化版 Beam Search）
*   **输入**：从实验 1 得到的 `high_resonance_topics`。
*   **步骤**：
    1.  让 LLM 基于每个 Topic 生成 3 个候选问题（共 9 个）。
    2.  **效用打分**：让 LLM 扮演“用户”，对每个问题打分（1-5 分，模拟点击意愿）。
    3.  **多样性打分**：计算 9 个问题两两之间的语义相似度（使用 Embedding 模型，如 `text-embedding-3-small`），相似度越低得分越高。
    4.  **组合筛选**：手动或写脚本选出 3 个问题组成的列表，使得 `总效用分 + 0.5 * 平均多样性分` 最大。
*   **期望输出**：一个包含 3 个问题的列表，且问题之间不重复（如：不全是问句，或话题跨度大）。
*   **验证**：对比“随机选 3 个”和“混合筛选选 3 个”，看后者是否更有趣。

### 实验 3：A/B 测试模拟（离线评估）
*   **输入**：100 个模拟用户的历史对话数据（可构造或脱敏真实数据）。
*   **步骤**：
    1.  **对照组**：使用通用 Prompt 生成开场白（如“你好，有什么可以帮你？”）。
    2.  **实验组**：使用 IceBreaker 流程（RID 提取兴趣 -> ISG 生成列表）。
    3.  **评估**：使用 LLM 作为裁判（Judge），让 LLM 扮演用户，判断哪种开场白更可能引发回复，并给出理由。
*   **期望输出**：实验组的“预测点击率”显著高于对照组（目标：提升 20% 以上）。
*   **验证**：统计 LLM 裁判的胜率。

## 产品 / Agent 灵感

1.  **“记忆唤醒”模式**：
    在用户长时间未登录后，Agent 不直接问“好久不见”，而是基于用户**最后一次活跃时的兴趣**生成开场。例如：“上次您聊到想学做意大利面，这周试了吗？我找到了一个新食谱。”
2.  **动态兴趣仪表盘**：
    将 IceBreaker 的 RID 模块可视化。在 Agent 设置页展示“当前最感兴趣的话题”，用户可手动调整（增加/删除），让 Agent 的开场白更精准。
3.  **多模态破冰**：
    不仅生成文本问题，结合 RID 识别的兴趣，直接生成**图片/视频**作为开场。例如识别到用户喜欢“露营”，开场列表第一项直接附带一张“绝美露营营地”的缩略图，点击即展开对话。
4.  **长尾兴趣挖掘器**：
    专门针对“沉默用户”，利用 RID 挖掘其历史中**极少提及但重访过**的冷门兴趣（如：用户只提过一次“观鸟”，但后来重访过），生成惊喜式开场：“发现您之前对观鸟很感兴趣，最近有发现新的鸟类吗？”

## 跟现有系统怎么接

1.  **数据层接入**：
    *   无需重构数据库。只需从现有的**用户行为日志**（User Logs）或**会话历史表**（Conversation History）中，抽取最近 N 条会话的摘要（Summary）或关键词（Tags）。
    *   如果现有系统没有“会话摘要”，先跑一个轻量级 LLM 对历史对话做摘要（Summarization），存入用户画像表。

2.  **推理层接入**：
    *   **前置服务**：在用户打开 App 的 API 网关层，增加一个 `IceBreaker` 微服务。
    *   **流程**：用户请求 -> 获取用户 ID -> 调用 RID 模块（异步或同步，视延迟要求） -> 获取兴趣列表 -> 调用 ISG 模块（生成列表） -> 返回给前端展示。
    *   **延迟优化**：RID 模块可以**离线/准实时**运行（如每 10 分钟更新一次用户兴趣缓存），ISG 模块在线运行，将总延迟控制在 500ms 以内。

3.  **反馈层接入**：
    *   在 UI 上为每个开场问题添加“点击/忽略”按钮。
    *   将点击数据作为**正样本**，忽略数据作为**负样本**，定期（如每周）重新训练 ISG 的 DPO 模型，实现自强化迭代。

## 风险与坑

1.  **新用户冷启动（Cold-Start for New Users）**：
    *   **风险**：RID 依赖历史数据，新用户无数据，模型可能生成通用废话，效果不如基线。
    *   **对策**：为新用户设计“兴趣探索问卷”（3 个简单选择题），或基于**设备信息/地理位置/下载来源**进行粗略的群体画像推荐（Group-based Personalization）。

2.  **隐私与合规**：
    *   **风险**：直接引用用户历史隐私（如“你上次说和老公吵架了”）可能引发反感或合规问题。
    *   **对策**：在 RID 阶段增加**敏感信息过滤层**（PII Redaction），只提取非敏感的“兴趣点”（如“家庭关系”而非具体事件），并在生成问题时使用模糊化表达。

3.  **幻觉与事实错误**：
    *   **风险**：ISG 模块可能编造用户从未提过的兴趣（如“您上次买的相机”其实用户没买过）。
    *   **对策**：在生成后增加**事实核查（Fact-Checking）**步骤，要求 LLM 回溯原始会话摘要，确认兴趣点确实存在，否则降级为通用开场。

4.  **多样性陷阱**：
    *   **风险**：过度追求多样性可能导致生成的问题“为了不同而不同”，偏离用户核心兴趣。
    *   **对策**：在混合奖励函数中，**效用（点击率）的权重必须高于多样性**。确保列表中的第一个问题必须是高置信度的核心兴趣。

## 跟进清单

- [ ] **数据准备**：提取最近 1000 个用户的历史会话摘要，构建测试数据集。
- [ ] **RID 原型**：编写 Python 脚本，实现基于“重访次数”的兴趣提取逻辑，验证准确率。
- [ ] **ISG 原型**：基于提取的兴趣，编写 Prompt 生成 3 个候选问题，并实现简单的多样性打分逻辑。
- [ ] **离线评估**：用 LLM Judge 对比“通用开场”与"IceBreaker 开场”的吸引力。
- [ ] **小流量测试**：选取 1% 的真实用户（或内部员工）进行 A/B 测试，监控 CTR 和 会话时长。
- [ ] **反馈闭环**：设计数据埋点，记录用户对每个开场问题的点击/忽略行为，为后续 DPO 训练做准备。
