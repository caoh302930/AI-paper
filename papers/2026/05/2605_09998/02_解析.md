## TL;DR and contributions
这篇论文提出了一种名为 **Continual Harness** 的框架，旨在解决具身智能体（Embodied Agents）在长程任务中无法像代码智能体那样自动优化其“脚手架”（Harness）的问题。核心突破在于：智能体无需重置环境，就能在单次游戏过程中，通过观察失败轨迹，实时自动重写自己的系统提示词、子智能体、技能库和记忆模块。实验表明，在《宝可梦》游戏中，该框架仅从最小化接口出发，就能自动进化出接近人工专家水平的策略，显著降低操作成本（按钮点击次数），并实现了开源模型与优化中 Harness 的在线协同学习。

**Main contributions:**
- 提出了 **Continual Harness**，首个支持“无重置（reset-free）”在线优化的具身智能体脚手架框架。
- 展示了 **Gemini Plays Pokémon (GPP)** 项目成果：首个完成多款《宝可梦》RPG（Blue, Yellow Legacy, Crystal）且无败绩的 AI 系统，验证了 Harness 迭代的有效性。
- 证明了 **模型-Harness 协同学习**：开源模型（Gemma-4）能在不重置环境的情况下，通过不断进化的 Harness 持续获得游戏进度提升。
- 揭示了 **能力依赖性**：Harness 的增益效果与基础模型能力强相关，强模型（Gemini Pro）下表现 Pareto 最优，弱模型（Flash-Lite）下甚至不如基线。

**Compared against:**
- $\mathcal{H}_{\min}$：最小化基线（仅截图 + 按键 + 通用提示词，无子智能体/记忆/技能）。
- $\mathcal{H}_{\text{expert}}$：人工专家设计的 Harness（包含预构建的路径规划、属性克制表、伤害计算器等）。
- 传统 Prompt 优化方法（如 GEPA）：需每轮重置环境，无法利用长程轨迹中的中间失败信号。

**On datasets:**
- **Pokémon Red** (Game Boy) 和 **Pokémon Emerald** (GBA)：作为具身智能体的长程决策基准。
- 评估指标：达到特定里程碑（Milestones）所需的**累计按钮点击次数**（Button Presses）。

**Headline improvements:**
- 在 Pokémon Emerald 上，使用 Gemini Pro 的 Continual Harness 达到 100% 里程碑完成度，成本从基线的 \$215 降至 \$130（**约 40% 成本降低**）。
- 在 Pokémon Red 上，开源模型 Gemma-4 通过协同学习，从游戏起点或中途存档点开始，均能持续推进游戏进度，而基线模型完全无法离开起始区域。

## What matters, what doesn't

- **🎯 Core idea (read carefully):** **无重置的在线 Harness 迭代**。核心在于 Refiner 模块能在单次游戏过程中（每 $F$ 步），读取最近轨迹，识别失败模式（如死循环、工具调用错误），并直接对 Harness 的四个组件（提示词 $p$、子智能体 $\mathcal{G}$、技能 $\mathcal{K}$、记忆 $\mathcal{M}$）进行 CRUD 操作。这与需要重置环境的传统方法有本质区别。
- **🔧 Useful in practice:** **Meta-tools 设计**。论文详细定义了 `define_agent`, `run_code`, `process_memory` 等元工具，使得智能体不仅能“用”工具，还能“写”工具。这是实现自动进化的关键接口。
- **📎 Nice to know:** **GPP 项目的演化史**。从早期人工干预到后期完全自动化，以及具体的失败案例（如 Power Plant 路线死循环），这些案例生动展示了为什么需要自动优化。
- **⚠️ Deprecated / superseded:** 传统的“重置 - 优化 - 再运行”范式（如 GEPA）在长程具身任务中效率低下，本文证明了在线连续优化的优越性。
- **🔕 Skippable:** 附录中关于具体超参数（如 LoRA rank=256）的详细表格，除非你要复现训练细节，否则只需关注结论。

## Context and prerequisites

要理解这篇论文，首先需要建立对 **Agentic Harness（智能体脚手架）** 的直观认识。在代码智能体（如 Claude Code）中，模型本身只是大脑，而 Harness 是它的“工具箱”和“操作手册”。它包含系统提示词（告诉模型该做什么）、子智能体（专门处理特定任务的模块，如搜索代码）、技能（可复用的代码片段或逻辑）和记忆（存储长期事实）。在具身智能体领域，尤其是像《宝可梦》这样的 RPG 游戏中，环境是部分可观测的（Partial Observability），且任务跨度极长（Long-horizon）。如果只给模型一个通用的提示词（$\mathcal{H}_{\min}$），它就像让一个没受过训练的人直接玩高难度游戏，几乎寸步难行。因此，必须有一个“脚手架”层来弥补模型能力的不足。

其次，需要理解 **Reset-free（无重置）训练** 的难点。传统的强化学习或提示词优化方法，通常在每一轮尝试失败后，都会把环境重置回初始状态（Reset）。这在模拟环境中很常见，但在真实世界或长程任务中，重置往往成本高昂甚至不可能（比如你不能让一个机器人把已经建好的房子拆了重来）。更重要的是，重置会切断“失败原因”与“修正动作”之间的因果链条。如果智能体在第 1000 步犯了一个导致第 5000 步失败的错误，重置后它永远无法在同一个上下文中学习到“因为第 1000 步的错误，所以我需要修改第 1000 步的策略”。Continual Harness 的核心创新正是打破了这种重置依赖，允许智能体在“带着伤”的状态下直接修补自己的策略。

最后，**在线上下文学习（Online In-Context Learning）** 是本文的方法论基础。不同于微调（Fine-tuning）需要更新模型权重，本文让智能体在推理过程中，通过读取历史轨迹，动态修改自己的“系统提示词”和“工具库”。这就像是一个人在玩游戏时，一边玩一边写笔记、改攻略，甚至发明新的操作技巧，而不是等游戏结束了再回去重练。

## Method

### The big picture (layman version)
想象你在玩一个极其复杂的《宝可梦》游戏，但你没有攻略，而且每走错一步，游戏不会让你读档重来，你必须继续走下去。Continual Harness 就像是你脑子里的一个“自我教练”。当你发现自己在某个地方转圈（死循环），或者打不过某个对手时，这个“教练”会立刻暂停你的思考（但不暂停游戏），分析刚才的操作记录，然后直接修改你的“游戏策略手册”（系统提示词），或者教你一个新的“连招”（技能），甚至让你记住“这个怪怕火”（记忆）。最关键的是，这一切发生在你继续玩的过程中，不需要重新开始游戏。随着游戏进行，你的策略手册越来越完善，你玩得越来越顺。论文不仅让强模型（Gemini）做到了这一点，还让开源模型（Gemma）通过这种“边玩边改攻略”的方式，学会了原本不会玩的关卡。

### The walkthrough

**1. 核心架构：双循环设计**
Continual Harness 包含两个嵌套的循环：
- **内循环（Inner Loop）：智能体行动**。智能体 $M$ 接收当前观察 $s_t = (o_t, m_t)$（图像 + 文本地图），结合当前的 Harness 状态 $\mathcal{H}_t$，输出动作 $a_t$。
- **外循环（Outer Loop）：Harness 优化**。每经过 $F$ 步（且过了预热期 $W$ 步），一个 **Refiner**（优化器）介入。Refiner 读取最近的时间窗口轨迹 $\tau_{t-F:t}$，识别“失败签名”（如导航死循环、工具调用失败、目标停滞）。

**2. Refiner 的四步优化机制**
Refiner 不是简单地修改提示词，而是对 Harness 的四个核心组件进行 **CRUD**（创建、读取、更新、删除）操作：
- **系统提示词 ($p$)**：重写指令，针对识别出的失败模式添加约束。例如：“如果在菜单中卡住，不要重复按 Down，尝试按 B 退出”。
- **子智能体 ($\mathcal{G}$)**：如果检测到重复的多步模式（如“打开菜单 -> 选择宝可梦 -> 使用技能”），Refiner 会创建一个新的子智能体来专门处理；如果某个子智能体长期无效，则删除它。
- **技能 ($\mathcal{K}$)**：将成功的操作序列固化为可执行的代码或启发式规则。例如，将“自动按按钮序列”封装为 `press_sequence` 工具。如果代码报错，Refiner 会尝试修复代码。
- **记忆 ($\mathcal{M}$)**：添加新的事实（如“这个 NPC 在下午 3 点出现”），更新过时的信息，或删除不再相关的记忆。

**3. 为什么不需要重置？**
这是本文最关键的数学与逻辑设计。传统方法（如 GEPA）的更新公式通常基于完整回合的奖励 $R(\tau)$，需要 $\tau$ 从头开始。而 Continual Harness 的更新基于局部轨迹窗口 $\tau_{t-F:t}$。
设 Harness 状态为 $\mathcal{H}_t$，更新操作为 $\Delta_t = \text{Refiner}(\tau_{t-F:t}, \mathcal{H}_t)$。
新的状态为 $\mathcal{H}_{t+1} = \mathcal{H}_t \oplus \Delta_t$。
这里的 $\oplus$ 表示状态合并（CRUD 操作）。关键在于，$\mathcal{H}_{t+1}$ 直接作用于 $t+1$ 时刻的决策，而环境状态 $s_{t+1}$ 是连续演化的。这意味着，**失败的原因（在 $t-F$ 到 $t$ 之间）和修正后的策略（在 $t+1$ 之后）处于同一个连续的时间流中**。智能体可以立即验证修正是否有效，如果无效，Refiner 会在下一个窗口继续修正。这种“在线修正”机制使得智能体能够处理长程依赖问题，因为早期的错误信号不会因重置而丢失。

**4. 模型-Harness 协同学习（Co-Learning Loop）**
论文进一步将这一框架扩展到模型权重的更新。
- **流程**：开源模型 $\pi_{\theta_k}$ 在正在优化的 Harness $\mathcal{H}_t$ 中运行 $K=256$ 步。
- **评分**：使用过程奖励模型（PRM）对轨迹中的每个步骤打分 $R(s_t, a_t, \tau)$。
- **重标注**：低分片段由强模型（Frontier Teacher，如 Gemini-3.1-pro）进行重标注（Relabeling），生成“正确答案”。
- **更新**：使用软 SFT（Soft SFT）更新模型权重 $\theta_{k+1}$。
- **无重置**：训练迭代 $k$ 结束时的模拟器状态直接作为 $k+1$ 的起点。
这使得模型不仅学会了“怎么玩”，还学会了“如何适应不断变化的攻略”，实现了真正的协同进化。

## Challenges in the field — and what this work addresses

**挑战 1：长程任务中的部分可观测性与规划崩溃**
*为什么难*：在《宝可梦》等 RPG 中，任务跨度长达数千步，且环境状态（如 NPC 位置、道具掉落）是部分可观测的。基础模型容易陷入局部最优（如死循环）或遗忘长期目标。传统的 Prompt Engineering 是静态的，无法应对动态出现的复杂情况。
*本文方案*：Continual Harness 通过**动态记忆和技能库**解决了这个问题。Refiner 能够根据实时轨迹，将临时性的成功策略固化为长期技能（如“自动寻路”），并更新记忆以消除信息盲区。这种“边做边学”的机制使得智能体能够处理长程依赖，而无需依赖预定义的完美规划。

**挑战 2：环境重置的高成本与因果断裂**
*为什么难*：现有的提示词优化方法（如 GEPA）依赖“重置 - 评估 - 优化”循环。在真实具身任务中，重置往往不可行（如机器人操作、长期运维）。此外，重置切断了“早期错误”与“后期修正”的因果联系，导致智能体无法从长程失败中学习。
*本文方案*：本文提出了**无重置（Reset-free）的在线优化**。Refiner 在单次轨迹中直接修改 Harness，使得修正动作能立即在后续步骤中生效。这不仅降低了环境交互成本，更重要的是保留了完整的失败因果链，使得智能体能够针对特定时间点的错误进行精准修复。

**挑战 3：模型能力与脚手架的匹配度**
*为什么难*：如果基础模型太弱，即使有再好的脚手架，也无法正确调用工具或理解指令；如果模型太强，可能不需要复杂的脚手架。如何平衡两者是一个开放问题。
*本文方案*：实验揭示了**能力依赖性（Capability-dependent gains）**。论文发现，对于强模型（Gemini Pro），Continual Harness 能带来显著的 Pareto 优势；但对于弱模型（Flash-Lite），优化过程甚至可能导致性能下降（低于基线）。这表明，Harness 的自动优化需要模型具备一定的“元认知”能力来理解并执行 Refiner 的修改。这为未来研究提供了重要方向：如何设计自适应的 Harness 以适配不同能力的模型。

## Experiments and results

**实验设置**：
- **环境**：Pokémon Red (GB) 和 Pokémon Emerald (GBA)。
- **基线**：$\mathcal{H}_{\min}$（最小化）、$\mathcal{H}_{\text{expert}}$（人工专家）、GEPA（重置式优化）。
- **模型**：Gemini 3 系列 (Pro, Flash, Flash-Lite) 和开源 Gemma-4 系列。
- **指标**：达到里程碑的累计按钮点击次数（越低越好）。

**关键结果**：
1. **效率提升**：在 Pokémon Emerald 上，Gemini Pro + Continual Harness 达到 100% 里程碑，成本为 \$130，而 $\mathcal{H}_{\min}$ 成本为 \$215（**降低约 40%**）。$\mathcal{H}_{\text{expert}}$ 虽然效率更高，但需要大量人工设计，而 Continual Harness 从零开始自动达到其 80% 以上的效率。
2. **能力阈值**：
   - **Gemini Pro**：Continual Harness 严格 Pareto 优于基线。
   - **Gemini Flash**：高方差，Bootstrap-updating 版本略优于基线（80% 完成度 vs 77%）。
   - **Gemini Flash-Lite**：所有 Continual Harness 变体均**低于**基线（完成度 3-13% vs 20%），说明模型能力不足以支撑自动优化，甚至被错误的优化误导。
3. **开源模型协同学习**：Gemma-4 (31B) 在 Pokémon Red 上，通过 Reset-free DAgger+PRM 循环，从游戏起点或中途存档点开始，均能持续推进里程碑。相比之下，未训练的基线模型完全无法离开起始区域。
4. **技能自进化**：导航技能的路径成本（相对于 Dijkstra 最优解）从初始的 50% 以上误差迅速下降到个位数，证明了技能库在单次运行中的自我修复能力。

## Open questions and limitations

1. **能力下限（Capability Floor）**：实验表明，当模型能力低于一定阈值（如 Flash-Lite）时，自动优化反而有害。未来的研究需要探索如何动态调整 Harness 的复杂度，或者设计更鲁棒的 Refiner 以防止弱模型“越改越错”。
2. **收敛性证明**：论文展示了持续的进步，但未证明算法会收敛到某个最优解。在无限长的轨迹中，Harness 是否会无限膨胀？是否存在“过度拟合”当前轨迹的风险？
3. **通用性验证**：目前仅在 Pokémon 游戏中验证。在更复杂的具身环境（如物理世界机器人操作、多智能体协作）中，Refiner 的延迟和计算开销是否可接受？
4. **记忆复用效率**：附录 C.1.4 指出，大多数生成的记忆条目从未被引用。如何设计更高效的记忆检索机制，避免“记忆爆炸”？
