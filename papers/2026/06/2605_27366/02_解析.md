# MUSE-Autoskill: Self-Evolving Agents via Skill Creation, Memory, Management, and Evaluation

**Authors:** Huawei Lin, Peng Li, Jie Song, Fuxin Jiang, Tieying Zhang (ByteDance Inc., Rochester Institute of Technology)
**Venue:** arXiv preprint (2026)
**Organization(s):** ByteBrain Team (ByteDance)

**Project page:** None

## TL;DR and contributions
这篇论文提出了一种名为 **MUSE-Autoskill** 的智能体框架，它不再把“技能（Skill）”看作是一次性生成的代码片段，而是将其视为具有完整生命周期的长期资产。该系统能自动创建、记忆、管理、评估和修补技能，让智能体在解决复杂任务时能像人类专家一样积累和复用经验。

**Main contributions:**
- 定义了技能的**五阶段生命周期**（创建、记忆、管理、评估、修补），填补了现有自动技能系统缺乏运行时上下文和系统化验证的空白。
- 提出了**技能级记忆（Skill-level Memory）**机制，为每个技能单独存储使用经验和失败教训，而非仅依赖全局记忆。
- 实现了**跨智能体技能迁移**，证明 MUSE 生成的技能可以直接被其他智能体（如 Hermes）复用且效果优于人类编写的技能。
- 在 **SkillsBench** 和 **SkillLearnBench** 上取得了 SOTA 性能，MUSE 自创技能在覆盖子集上的准确率（85.24%）甚至超过了人类编写技能（81.17%）。

**Compared against:** Hermes, Codex, Claude Code (均基于 GPT-5.5 后端)
**On datasets:** SkillsBench (75 个真实世界任务), SkillLearnBench (20 个任务，100 个实例)
**Headline improvements:**
- SkillsBench 人类技能准确率：MUSE **59.67%** vs 次优 57.58% (+2.09 pp)。
- SkillsBench 自创技能准确率：MUSE **53.42%** vs 次优 47.52% (+5.90 pp)。
- 跨智能体迁移：MUSE 技能让 Hermes 从 37.24% 提升至 **51.90%**，超越了 Hermes 使用人类技能的 48.02%。

## What matters, what doesn't

- **🎯 Core idea (read carefully):** 技能的“生命周期管理”视角。核心在于将技能从静态代码升级为动态资产，特别是**技能级记忆**（记录每个技能的具体失败模式）和**基于单元测试的自动评估/修补**闭环。
- **🔧 Useful in practice:** 自适应上下文压缩策略（DAG 结构 + 两级压缩），以及技能包的目录结构规范（SKILL.md + tests/ + .memory.md），这对构建可维护的 Agent 系统极具参考价值。
- **📎 Nice to know:** 具体的超参数设置（如压缩阈值 180K tokens）、不同任务域（科学、数据、文档等）的细分表现分析。
- **⚠️ Deprecated / superseded:** 传统的“一次性生成即结束”的 AutoSkill 范式（如早期 Voyager 或 AutoSkill 的部分实现），它们缺乏跨任务的记忆积累和自动修补机制。

## Context and prerequisites

要理解这篇论文，首先需要打破对“智能体技能”的固有认知。在早期的 LLM Agent 研究中，技能通常被视为固定的工具列表（Tool Registry）或者一次性生成的代码脚本。这就好比给一个实习生发了一本操作手册，用一次就扔，下次遇到同样问题还得重新读一遍手册。这种模式导致智能体无法从过去的成功或失败中积累“肌肉记忆”。

其次，需要理解**上下文窗口（Context Window）的局限性**。随着任务步骤增加，对话历史会迅速膨胀，导致关键信息被截断或模型“迷失在中间（Lost in the Middle）”。MUSE 论文中的上下文管理模块正是为了解决这个问题，它不仅仅是简单的截断，而是通过有向无环图（DAG）记录完整历史，并智能地压缩中间节点，保留首尾关键信息。

最后，**技能的生命周期（Lifecycle）**概念至关重要。在软件工程领域，代码有开发、测试、部署、维护的周期。MUSE 将这一理念引入 Agent 领域，认为技能也应该有“创建（解决新问题）-> 评估（单元测试验证）-> 记忆（记录经验）-> 管理（去重、合并）-> 修补（根据失败反馈更新）”的完整闭环。没有这个闭环，技能就是死的；有了它，技能才能像生物一样进化。

## Method

### The big picture (layman version)
想象 MUSE-Autoskill 是一个拥有“超级学徒”能力的机器人。当它遇到一个从未做过的新任务时，它不会盲目地试错，而是先检查自己的“技能库”。如果没有现成的技能，它会启动“技能创建”模式：像程序员一样编写代码、写文档（SKILL.md），并自动编写测试用例来验证自己写的代码对不对。一旦验证通过，这个技能就会被“存档”，并且系统会专门在这个技能旁边记一本小账本（技能级记忆），记录“上次用这个技能时，输入格式有点特殊，容易报错”。下次再遇到类似任务，它不仅能调用这个技能，还能根据小账本里的经验避开之前的坑。如果技能用错了，系统会自动触发“修补”程序，修改代码直到测试通过。整个过程就像是一个不断自我进化的工匠，越做越熟练，而且它做的工具（技能）还能直接借给别的机器人用。

### The walkthrough

MUSE-Autoskill 的核心架构围绕**ReAct 循环**（Reasoning-Acting-Observing）展开，但引入了一个关键的**技能生命周期管理模块**。

**1. 技能的定义与结构**
首先，MUSE 将技能（Skill）定义为一种结构化的目录包，遵循 Anthropic 的 Agent Skills 格式。一个技能包包含：
- `SKILL.md`：定义接口、描述、输入输出规范。
- `scripts/`：可执行代码（Python/Shell 等）。
- `tests/`：单元测试脚本（这是 MUSE 的关键创新，用于自动验证）。
- `.memory.md`：**技能级记忆**，这是 MUSE 独有的。它不是全局记忆，而是依附于特定技能，记录该技能在历史任务中的表现、失败模式和特殊输入要求。

**2. 技能创建（Creation）：从“试错”到“工程化”**
当智能体发现现有技能不足以解决问题时，会调用内置的 `skill_create` 工具。
- **动机**：传统的 AutoSkill 往往直接生成代码，缺乏验证，导致生成的技能不可靠。
- **过程**：智能体根据任务需求生成 `SKILL.md` 和代码。关键在于，如果生成了代码，MUSE 会**自动生成测试用例**（或复用已有的验证逻辑）。
- **验证闭环**：生成的技能包必须在沙箱（Sandbox）中运行测试。只有测试通过，技能才会被注册到技能库；如果失败，系统会捕获错误日志，触发**修补（Refinement）**流程，修改代码直到通过。这确保了进入库中的技能都是“经过质检”的。

**3. 技能记忆（Memory）：三级记忆架构**
MUSE 设计了三层记忆系统来解决长程任务和经验积累问题：
- **短期记忆（Short-term）**：当前任务的上下文，包含中间推理步骤。
- **长期记忆（Long-term）**：跨会话的通用经验（如“某类 API 需要特定的认证头”）。
- **技能级记忆（Skill-level Memory）**：**这是核心**。每个技能包旁附带一个 `.memory.md` 文件。当技能被调用时，不仅加载 `SKILL.md`，还会加载 `.memory.md`。
  - *作用*：如果某个技能在特定输入下容易出错，记忆文件会提示智能体“注意输入格式”或“先执行预处理”。这使得技能具备了“上下文感知”的进化能力。

**4. 上下文管理（Context Management）：DAG 与自适应压缩**
为了处理长任务，MUSE 将对话历史建模为**有向无环图（DAG）**，每个节点代表一个 ReAct 步骤（Plan, Action, Observation）。
- **两级压缩策略**：
  - **Level-1（单节点压缩）**：如果某个步骤的输出（如长日志）过长，单独压缩该节点，保留结构。
  - **Level-2（链式压缩）**：如果总长度仍超限，将中间连续的一段节点合并为一个合成节点。
- **锚点机制**：始终保留前 `KEEP_FIRST` 和后 `KEEP_LAST` 个节点（默认各 5 个），确保任务目标和当前状态不被压缩丢失。原始历史保留在 DAG 中，随时可回溯。

**5. 技能管理（Management）与跨智能体迁移**
- **管理**：系统定期扫描技能库，合并冗余技能，删除长期未用或持续失败的技能。
- **迁移**：由于技能是标准化的文件包（不依赖特定模型权重），MUSE 生成的技能可以直接被其他智能体（如 Hermes）加载使用。实验证明，这种迁移不仅可行，而且效果显著。

## Challenges in the field — and what this work addresses

**挑战一：技能生成的“一次性”与“不可靠”**
- **难点**：现有方法（如 Voyager, AutoSkill）生成的技能往往是“一次性”的，缺乏系统化的验证。生成的代码可能只在当前任务跑通，换个环境就报错，且没有机制去修复它。
- **MUSE 的解法**：引入**单元测试驱动的评估与修补闭环**。技能不再是“生成即结束”，而是必须通过测试才能入库。如果失败，自动触发修补。这使得技能从“草稿”变成了“工程产品”。

**挑战二：经验积累的碎片化**
- **难点**：传统 Agent 的记忆通常是全局的（如整个对话历史），导致特定技能的“使用心得”淹没在海量信息中。智能体无法记住“技能 A 在输入 X 时容易出错”这种细粒度经验。
- **MUSE 的解法**：首创**技能级记忆（Skill-level Memory）**。将经验绑定到具体技能上，使得技能本身携带了“使用说明书”和“避坑指南”，实现了真正的经验复用。

**挑战三：长程任务中的上下文爆炸**
- **难点**：随着任务步骤增加，上下文窗口迅速耗尽，导致模型遗忘关键信息或产生幻觉。简单的截断会丢失逻辑链条。
- **MUSE 的解法**：基于 DAG 的**自适应上下文压缩**。通过区分“关键节点”和“可压缩节点”，在保留完整逻辑链条的同时，动态控制 Token 消耗，支持超长任务。

**MUSE 未解决的问题**：
- **覆盖度瓶颈**：虽然 MUSE 生成的技能质量高，但仍有约 37% 的任务（28/75）无法生成可用的初始技能（即 Phase 1 探索失败）。目前的系统依赖于先有一个成功的轨迹才能提炼技能，对于完全无法探索出路径的难题，MUSE 目前无能为力。

## Experiments and results

实验在 **SkillsBench**（75 个任务，5 次运行）和 **SkillLearnBench**（20 个任务，100 个实例）上进行，对比基线包括 Hermes, Codex, Claude Code（均使用 GPT-5.5 后端）。

**1. 技能使用的效果（Effect of Skill Usage）**
- **人类技能**：MUSE 使用人类技能达到 **59.67%** 准确率，显著高于 Hermes (48.02%) 和 Codex (57.58%)。
- **自创技能**：MUSE 自创技能达到 **53.42%**，优于 Codex (47.52%) 和 Claude Code (44.27%)。
- **结论**：MUSE 不仅擅长使用技能，更擅长创造高质量技能。

**2. 自创技能的质量（Automatic Skill Generation）**
- 在**覆盖子集**（即成功生成技能的任务）上，MUSE 自创技能准确率达到 **85.24%**，甚至超过了同一子集上人类技能的 **81.17%**。
- 这表明，一旦 MUSE 成功提炼出技能，其质量极高，甚至能超越人工编写。
- **瓶颈**：主要问题在于**覆盖率**。MUSE 和 Codex 都只能覆盖 47/75 的任务，剩余任务因无法生成初始轨迹而得 0 分。

**3. 跨智能体迁移（Cross-Agent Skill Transfer）**
- 将 MUSE 生成的技能直接注入 Hermes：Hermes 准确率从 37.24% 提升至 **51.90%**。
- **关键发现**：MUSE 生成的技能在 Hermes 上的表现（51.90%）**超过了 Hermes 使用人类技能的表现（48.02%）**。这证明了 MUSE 生成的技能具有极强的通用性和高质量，超越了人工编写的技能。

**4. 成本分析**
- **Token 成本**：MUSE 自创技能的一次性生成成本为 364K tokens，但复用成本极低。
- **摊销效应**：生成技能的成本在复用约 3 次后即可被节省的 Token 抵消。
- **延迟**：自创技能将中位延迟从 729s 降至 434s，显著提升了效率。

## Open questions and limitations

1. **初始探索的局限性**：MUSE 严重依赖 Phase 1 的成功轨迹来生成技能。如果智能体在初始探索中完全失败（无法找到任何可行路径），则无法生成技能。如何从“失败轨迹”中提取部分有用的技能（Partial Skill）是一个未解决的难题。
2. **幻觉风险**：尽管有单元测试，但生成的技能仍可能包含对特定环境（如特定文件路径、特定数据格式）的硬编码假设，导致在分布外（OOD）数据上失效。
3. **迁移的广度**：目前的跨智能体迁移仅在 Hermes 上进行了验证。不同架构的智能体（如基于不同 Prompt 策略或工具调用机制的 Agent）是否能无缝兼容 MUSE 技能，仍需更多验证。
4. **成本与收益的平衡**：虽然复用成本低，但生成高质量技能的一次性 Token 成本（364K）仍然较高，对于低频任务可能不划算。
