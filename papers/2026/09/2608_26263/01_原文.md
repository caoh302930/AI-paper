### 视频简介

EMNLP26-SKILL.state: Scalable Long-Horizon Agent Skills
https://arxiv.org/abs/2608.26263

1. 论文核心：SKILL.state 用技能说明、当前结构化状态和最新观察驱动每一步执行，校验状态补丁后丢弃本步推理。
2. 问题背景：持续追加历史会让 prompt 随任务变长，旧动作和无关观察还会干扰模型对当前事实的判断。
3. 运行时循环：模型提出动作与状态补丁，程序检查字段、类型和格式，合并下一状态后执行动作。
4. 状态模式：状态不是自由摘要，而是按领域预先定义的字段；InterCode CTF 示例包含 flag、假设、活动文件、工作目录和命令摘要。
5. 长程成本：Warehouse 执行 200 步时，Memory 基线使用 6,175,509 个 token，SKILL.state 使用 122,384 个，分数分别为 0.84 和 0.94。
6. 抗噪与恢复：加入 50 个无关事件后，SKILL.state 分数仍为 0.98；外部库存变化到达纠正性观察后，测试中不需要额外恢复步。
7. 公开任务：InterCode CTF pass@1 为 54.2%，τ-Bench Retail 为 58.3%，Airline 为 32.4%，效率收益也出现在工具调用任务中。
8. 关键对照：输入同样短时，截断、摘要和统计压缩的得分明显低于结构化状态，说明核心不是单纯减少文字。
9. 系列定位：WikiSkill关注跨轮知识积累，SkillOpt和Trace2Skill关注技能改进，SKILL.state补充技能选定后的长程执行状态管理。
10. 使用限制：方法依赖提前设计的状态模式，不适合必须回看历史轨迹的目标；多 Agent 并发写状态还需要确定性的冲突处理。
