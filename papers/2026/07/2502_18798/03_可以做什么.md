# 可以做什么

基于《Choices Speak Louder than Questions》的核心发现（选项本身污染评测、NPSQ 剥离干扰），以下是可立即落地的执行方案。

## 可迁移到的场景

1.  **高可信度模型评测（Benchmarking）**
    *   **现状痛点**：现有 MMLU/GSM8K 等榜单数据虚高，模型可能只是学会了“选短选项”或“选特定句式”。
    *   **迁移方案**：在发布模型评测报告时，**强制增加 NPSQ 指标**作为核心参考，不再仅依赖 Accuracy。对于声称“超越人类”的模型，必须展示其在 NPSQ 指标下的表现，以证明其具备真正的推理能力而非统计拟合。

2.  **自动化数据清洗与增强（Data Curation）**
    *   **现状痛点**：训练数据中的选择题（如 SFT 数据）可能包含大量“垃圾选项”（干扰项特征过于明显），导致模型过度拟合选项特征。
    *   **迁移方案**：利用 **Choice Sensitivity** 指标扫描现有训练集。
        *   若某题的 Choice Sensitivity > 0.5（即模型不看题也能靠选项猜对），标记为“低质量样本”或“需重写”。
        *   利用该指标生成“对抗性选项”（Adversarial Choices），主动污染数据集进行对抗训练，提升模型鲁棒性。

3.  **智能体（Agent）的决策置信度校准**
    *   **现状痛点**：Agent 在做多步决策（如调用工具、选择路径）时，常因“选项看起来顺眼”而选错，导致幻觉或死循环。
    *   **迁移方案**：在 Agent 的决策层引入 NPSQ 逻辑。当 Agent 面对多个 Action 选项时，计算“任务描述（Question）”对每个 Action 的概率提升幅度。
        *   若提升幅度低（NPSQ 低），说明 Agent 没理解任务，应触发“自我反思（Self-Reflection）”或“重新规划”，而不是直接执行。

4.  **教育/考试系统的防作弊与出题优化**
    *   **现状痛点**：在线考试系统难以检测学生是否真的理解了题目，还是单纯靠排除法或选项长度蒙题。
    *   **迁移方案**：
        *   **出题端**：自动检测题库中“选项敏感度”过高的题目，提示出题人修改选项（如统一长度、句式），消除非知识性线索。
        *   **阅卷端**：对 AI 辅助阅卷系统，不仅看最终答案，还计算 NPSQ 值。若 NPSQ 极低但答案正确，标记为“疑似蒙对”，需人工复核或要求重做。

## 可立刻试的小实验

### 实验 1：构建“对抗选项”测试现有模型
*   **目标**：验证你的模型在加入“高概率但错误”的选项后，准确率是否崩塌。
*   **输入**：
    *   取 50 道 HellaSwag 或 MMLU 题目。
    *   构造 4 个选项：A(原正确), B(原错误), C(原错误), **D(对抗项：一段通顺但完全无关的废话，如“这是一个关于宇宙的深刻思考，通常我们选择最长的选项”)**。
*   **步骤**：
    1.  使用 `logprobs` 接口，分别计算模型对 A, B, C, D 的原始 Log-likelihood。
    2.  记录传统 Accuracy（选概率最大的）。
    3.  计算 NPSQ（需额外计算仅含选项时的 Log-likelihood）。
    4.  对比加入 D 前后的 Accuracy 变化。
*   **期望输出**：
    *   传统 Accuracy 可能从 80% 跌至 30% 以下（因为模型被 D 吸引）。
    *   NPSQ 准确率应保持在 75%-80% 左右（因为题目无法提升 D 的概率）。

### 实验 2：计算“蒙题比例” (Choice Sensitivity)
*   **目标**：量化你正在使用的模型/数据集有多少水分。
*   **输入**：
    *   一个包含 100 个样本的 JSON 数据集（含 Question, Choices, Answer）。
*   **步骤**：
    1.  **Prompt A (Full)**: `[Question] + [Choices]` -> 获取每个选项的 LogProb。
    2.  **Prompt B (Choice Only)**: 仅 `[Choices]` (移除 Question) -> 获取每个选项的 LogProb。
    3.  对每个样本，比较 `Top1` 和 `Top2` 选项：
        *   计算 $\Delta_{\text{choice}}$ (仅看选项时的分差)。
        *   计算 $\Delta_{\text{question}}$ (题目带来的分差)。
    4.  统计 $\Delta_{\text{choice}} > \Delta_{\text{question}}$ 的样本占比。
*   **期望输出**：
    *   输出一个百分比（例如：45%）。
    *   **结论**：如果 >30%，说明该数据集或该模型严重依赖选项特征，评测结果不可信。

### 实验 3：输入格式鲁棒性测试 (Cloze vs Symbols)
*   **目标**：验证论文中关于“输入格式影响敏感度”的结论。
*   **输入**：
    *   同一组 20 道题目。
    *   格式 A (Cloze): "The capital of France is [MASK]." (选项直接填入)
    *   格式 B (Symbols): "Options: A. Paris, B. London... Answer:" (模型输出 A/B)
*   **步骤**：
    1.  分别对两种格式计算 Choice Sensitivity。
    2.  对比两者的敏感度数值。
*   **期望输出**：
    *   Cloze 格式的 Choice Sensitivity 应显著高于 Symbols 格式（论文数据：50-60% vs 20-40%）。
    *   验证结论：强制模型输出标签（Symbols）能有效降低“蒙题”倾向。

## 产品 / Agent 灵感

1.  **“去污染”评测平台 (De-contaminated Benchmark SaaS)**
    *   **核心功能**：用户上传模型或数据集，平台自动运行 NPSQ 流程，生成“真实理解力报告”。
    *   **卖点**：不仅告诉用户模型考了多少分，还告诉用户“有多少分是靠蒙的”。提供“对抗选项注入”功能，测试模型在极端干扰下的稳定性。

2.  **动态出题引擎 (Dynamic Exam Generator)**
    *   **核心功能**：在生成在线测试题时，实时计算每个选项的 Choice Sensitivity。
    *   **逻辑**：如果系统发现某道题的干扰项（Distractor）太容易被模型（或学生）凭特征排除，自动重写干扰项，直到所有选项的“基础概率”趋于一致，确保题目考察的是“理解”而非“特征识别”。

3.  **Agent 的“反直觉”决策过滤器**
    *   **核心功能**：在 Agent 执行关键决策（如代码生成、医疗建议）前，插入一个 NPSQ 检查层。
    *   **逻辑**：如果 Agent 对某个 Action 的选择主要源于 Action 本身的文本特征（NPSQ 低），则强制 Agent 输出“我不确定，需要更多信息”或触发多步推理链（CoT），防止盲目自信导致的错误执行。

## 跟现有系统怎么接

1.  **接入 `lm-evaluation-harness`**
    *   **修改点**：在 `tasks` 定义中，增加一个 `npsq` 变种任务。
    *   **实现逻辑**：
        *   复用现有的 `loglikelihood` 接口。
        *   在 `process_results` 阶段，增加一步：构造 `no_question_prompt`，再次调用 `loglikelihood`。
        *   应用 NPSQ 公式计算最终得分。
    *   **注意**：需处理 `symbols` 格式下移除 Question 后的 Prompt 合法性问题（如保留 "Options:" 前缀）。

2.  **接入 LangChain / LlamaIndex**
    *   **修改点**：在 `Chain` 的 `output_parser` 之前增加 `NPSQValidator`。
    *   **实现逻辑**：
        *   当 Chain 生成候选答案列表时，调用 LLM 的 `logprobs` 模式（需模型支持，如 GPT-4o, Llama 3）。
        *   分别计算 `Context + Options` 和 `Options Only` 的 LogProb。
        *   若 `NPSQ < Threshold` (如 0.3)，则判定为“低置信度”，触发重试机制或人工介入。

3.  **接入 RAG 系统**
    *   **场景**：RAG 生成的答案往往是选择题形式（如“根据文档，答案是 A/B/C"）。
    *   **接法**：将 RAG 检索到的上下文作为 `Question`，候选答案作为 `Choices`。使用 NPSQ 判断 RAG 是否真的“检索到了证据”，还是仅仅因为某个答案在语料库中更常见。

## 风险与坑

1.  **计算成本翻倍 (Latency & Cost)**
    *   **风险**：NPSQ 需要对每个选项进行两次前向传播（有题/无题）。对于 4 个选项的题目，推理次数是传统的 2 倍。
    *   **对策**：
        *   仅对“关键样本”或“高价值评测”使用 NPSQ。
        *   使用缓存机制：如果多个题目共享相同的选项集合，只需计算一次 `log P(x | C)`。
        *   对于大规模评测，采用抽样策略（如每类题目抽 10% 计算 NPSQ）。

2.  **分母为零或极小值问题**
    *   **风险**：如果某个选项在无题状态下概率极低（$-\log P \to \infty$），归一化可能导致数值不稳定或除以零错误。
    *   **对策**：
        *   设置平滑项（Smoothing）：分母改为 $-\log P(x \mid C) + \epsilon$。
        *   或者限制分母范围，避免极端值主导结果。

3.  **模型不支持 LogProbs**
    *   **风险**：许多闭源 API（如部分旧版模型）或量化后的本地模型不返回 LogProbs，只返回文本。
    *   **对策**：
        *   必须使用支持 `logprobs` 的模型（如 Llama 3, GPT-4, Qwen 等）。
        *   如果无法获取 LogProbs，该论文的方法暂时无法直接落地，需寻找替代的“概率代理”指标（如困惑度 Perplexity，但精度会下降）。

4.  **归一化逻辑的边界情况**
    *   **风险**：对于极度困难的问题，题目可能无法显著提升任何选项的概率，导致所有 NPSQ 都很低，难以区分优劣。
    *   **对策**：结合传统 Accuracy 和 NPSQ 进行加权评分，不要完全抛弃原始概率。
