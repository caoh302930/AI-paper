# 可以做什么：PiEvo 落地与发散指南

PiEvo 的核心价值在于**将“科学原理”从静态约束变为动态变量**，利用“异常数据”作为触发器，驱动 Agent 自我修正认知模型。这种“异常驱动的原理演化”范式，不仅适用于材料发现，可迁移至任何**高成本试错、强依赖先验假设、且存在未知规律**的复杂决策场景。

## 可迁移到的场景（≥4）

1.  **新药研发中的“脱靶效应”解释与机制重构**
    *   **痛点**：传统 AI 药物筛选基于已知靶点机制，当化合物出现非预期的副作用（异常数据）时，往往被直接丢弃。
    *   **PiEvo 应用**：将“副作用”视为异常证据，触发原理扩充。让 Agent 生成新的药理机制假设（如“该分子通过非经典通道影响代谢”），指导后续合成，将副作用转化为新适应症发现。

2.  **工业故障诊断与根因分析（RCA）**
    *   **痛点**：运维 Agent 依赖历史故障库（固定先验）。当出现从未见过的新型故障模式时，Agent 会反复尝试已知修复方案，导致停机时间延长。
    *   **PiEvo 应用**：监控传感器数据，当预测误差超过阈值（异常）时，不直接报警，而是触发“原理演化”。让 Agent 结合日志生成新的故障假设（如“温度与振动耦合导致的共振”），并设计验证性测试（如微调转速），快速定位未知根因。

3.  **金融量化策略的“黑天鹅”自适应**
    *   **痛点**：量化模型基于历史统计规律（固定先验），在市场结构突变（如政策突变、地缘冲突）导致策略失效时，模型往往过度拟合噪声或陷入死循环。
    *   **PiEvo 应用**：将市场异常波动视为“原理失效”信号。触发机制让 Agent 生成新的市场微观结构假设（如“流动性枯竭导致的非线性反馈”），动态扩充策略空间，而非单纯调整参数。

4.  **教育/培训中的“认知冲突”自适应教学**
    *   **痛点**：自适应学习系统基于学生知识图谱（固定先验）。当学生连续答错同类题（异常）时，系统通常只降低难度，无法识别学生是否存在根本性的“错误概念模型”。
    *   **PiEvo 应用**：将学生的错误答案视为“异常证据”。触发原理扩充，让 Agent 诊断学生潜在的“错误认知原理”（如“认为力是维持运动的原因”），生成针对性的反例实验或解释，重构学生的认知模型，而非仅仅推送更简单的题。

## 可立刻试的小实验（≥3）

### 实验 1：模拟“固执 Agent"的突破
*   **目标**：验证在固定先验失效时，引入异常检测能否跳出局部最优。
*   **输入**：
    *   一个 2D 函数 $f(x, y)$，其中全局最优解位于 $x>5$ 区域，但初始先验假设认为最优解在 $x<2$。
    *   一个模拟 Agent，初始策略仅搜索 $x \in [0, 2]$。
*   **步骤**：
    1.  运行基础 Agent 进行 20 次随机搜索，记录收敛情况（应卡在局部最优）。
    2.  引入 PiEvo 逻辑：当搜索点 $x$ 处的函数值 $y$ 与当前模型预测偏差 $>3\sigma$ 时，标记为“异常”。
    3.  触发“原理扩充”：强制 Agent 将搜索空间扩展至 $x \in [0, 10]$，并重新初始化 GP 模型。
    4.  继续搜索 20 次。
*   **期望输出**：
    *   基础 Agent 停留在 $x \approx 1.5$ 的局部最优。
    *   PiEvo 版 Agent 在检测到异常后，成功跳出 $x<2$ 区域，找到 $x>5$ 的全局最优解，且收敛步数显著减少。

### 实验 2：LLM 生成“伪原理”的过滤测试
*   **目标**：测试 LLM 在异常触发时生成新原理的质量，验证是否需要“相干性”过滤。
*   **输入**：
    *   一组化学分子数据，其中包含 3 个“异常点”（活性极高但结构不符合现有规则）。
    *   Prompt：请根据以下异常数据，提出一个新的化学合成原理。
*   **步骤**：
    1.  输入异常数据给 LLM，获取 5 个生成的新原理。
    2.  人工或规则引擎（如检查物理守恒、已知化学键规则）对原理进行“相干性打分”。
    3.  将得分最高的原理加入“活跃原理池”，重新运行贝叶斯优化。
    4.  对比直接加入所有原理 vs 过滤后加入的收敛速度。
*   **期望输出**：
    *   直接加入所有原理会导致优化方向发散或收敛极慢（因为包含了荒谬假设）。
    *   经过“相干性”过滤后，Agent 能利用正确的新原理快速收敛到高分解。

### 实验 3：信息导向采样（IDS）vs 贪婪采样
*   **目标**：验证“减少原理不确定性”比“直接找高分”在早期更高效。
*   **输入**：
    *   两个互斥的假设模型（Model A: 线性关系; Model B: 指数关系），真实数据符合 Model B。
    *   初始数据极少（仅 3 个点，且位于线性区，无法区分 A/B）。
*   **步骤**：
    1.  **Group A (贪婪)**：选择预测值最高的点作为下一个实验点。
    2.  **Group B (IDS)**：选择能最大程度区分 Model A 和 Model B 的点（即不确定性最高的点）。
    3.  各运行 10 轮，记录哪个模型被正确识别。
*   **期望输出**：
    *   Group A 可能继续在“线性区”打转，误判 Model A 为真。
    *   Group B 会主动选择“非线性区”的点，快速证伪 Model A，确立 Model B，从而指导后续优化。

## 产品 / Agent 灵感

1.  **“认知进化”型研发助手 (R&D Co-pilot)**
    *   **功能**：不仅推荐实验方案，还维护一个“理论假设库”。当实验失败时，它不报“失败”，而是报“理论冲突”，并生成 3 个新的理论假设供科学家选择验证。
    *   **卖点**：将“试错”转化为“理论发现”，提升科研人员的认知效率。

2.  **动态故障根因分析引擎 (Dynamic RCA Engine)**
    *   **功能**：在 SRE 系统中，当监控指标异常且现有知识库无匹配时，自动触发“假设生成器”，提出新的故障链条，并生成“验证性脚本”（如：尝试重启某服务看是否恢复，或调整某参数看趋势）。
    *   **卖点**：解决“未知故障”处理慢的问题，减少 MTTR（平均修复时间）。

3.  **自适应策略交易机器人 (Adaptive Alpha Bot)**
    *   **功能**：内置多个市场微观结构模型。当市场波动超出模型预测范围时，自动暂停交易，生成新的市场结构假设，并在模拟盘验证通过后，动态切换策略权重。
    *   **卖点**：避免在极端行情下因模型僵化而爆仓。

4.  **认知冲突诊断导师 (Cognitive Conflict Tutor)**
    *   **功能**：在在线学习平台中，当学生连续犯错时，不直接给答案，而是分析其错误模式，推断其“错误认知原理”，并推送针对性的“反直觉实验”或“苏格拉底式提问”来打破错误认知。
    *   **卖点**：从“刷题”升级为“概念重构”，提升深度学习效果。

## 跟现有系统怎么接

1.  **作为“异常拦截器”插件**
    *   **接入点**：现有 Agent 的“执行 - 反馈”循环中。
    *   **逻辑**：在现有 Agent 输出结果后，增加一层 `AnomalyChecker`。如果 `|Observed - Predicted| > Threshold`，则拦截当前流程，调用 `PrincipleGenerator` (LLM) 生成新假设，并重置 `Optimizer` 的搜索空间。
    *   **优势**：无需重构现有 Agent 核心，即插即用。

2.  **替换“策略选择器”模块**
    *   **接入点**：现有贝叶斯优化或强化学习框架的 `Acquisition Function` 部分。
    *   **逻辑**：将标准的 `Expected Improvement (EI)` 替换为 PiEvo 的 `IDS` 公式。需要引入 GP 模型来量化不确定性，并维护一个“原理集合”而非单一模型。
    *   **优势**：直接提升探索效率，特别适合小样本场景。

3.  **构建“双循环”架构层**
    *   **接入点**：在现有系统之上构建一个 `Meta-Agent` 层。
    *   **逻辑**：
        *   **内循环**：现有 Agent 负责具体实验/执行。
        *   **外循环**：Meta-Agent 监控内循环的“异常率”。一旦触发，Meta-Agent 调用 LLM 更新“原理库”，并重新配置内循环 Agent 的 Prompt 或约束条件。
    *   **优势**：解耦执行与认知，便于独立迭代。

## 风险与坑

1.  **LLM 幻觉导致的“原理污染”**
    *   **风险**：LLM 可能生成看似合理但物理上荒谬的原理（如“永动机机制”），导致 Agent 浪费宝贵实验资源去验证。
    *   **对策**：必须引入**“相干性过滤器”**（Coherence Filter）。在原理加入集合前，需通过物理规则检查、专家知识库检索或小型模拟验证，确保新原理与已知基本定律不冲突。

2.  **计算开销激增**
    *   **风险**：维护多个 GP 专家模型 + 频繁调用 LLM 进行原理推理，会导致推理延迟（Latency）和计算成本（Cost）呈指数级上升。
    *   **对策**：
        *   限制活跃原理数量（如只保留 Top-3 概率最高的原理）。
        *   使用蒸馏模型或小型 LLM 处理原理生成。
        *   仅在“高置信度异常”时触发原理扩充，而非每次小波动。

3.  **阈值 $\theta$ 的敏感性**
    *   **风险**：异常检测阈值设置不当。太敏感会导致频繁触发原理扩充，系统震荡；太迟钝则无法捕捉真正的异常，陷入局部最优。
    *   **对策**：实现**动态阈值调整机制**。根据历史数据的噪声水平自适应调整 $\theta_t$，或采用“累积异常计数”而非单次异常作为触发条件。

4.  **原理空间的无限膨胀**
    *   **风险**：随着实验进行，原理集合 $\mathcal{P}_t$ 可能无限增长，导致贝叶斯更新计算量过大。
    *   **对策**：引入**原理剪枝机制**。定期评估各原理的后验概率，剔除概率极低或解释力弱的原理，保持集合精简。
