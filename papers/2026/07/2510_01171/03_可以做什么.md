# 可以做什么

基于 Verbalized Sampling (VS) 的核心发现——**“通过让模型口头描述候选分布（而非直接生成实例）来绕过人类典型性偏差”**，以下是可立即落地的执行方案。

## 可迁移到的场景

1.  **创意内容生成引擎（营销/写作/剧本）**
    *   **痛点**：AI 生成的广告语、故事开头、营销文案千篇一律，缺乏“惊喜感”。
    *   **应用**：不再要求“写 3 个广告语”，而是要求“列出 5 种不同风格的广告语方案，并给出每种方案在目标用户中的预估点击概率分布”。
    *   **价值**：强制模型跳出“最安全”的文案模式，挖掘长尾创意，同时利用概率描述筛选出既新颖又合理的选项。

2.  **高保真用户模拟与压力测试（Agent 训练/产品测试）**
    *   **痛点**：用 RLHF 模型模拟用户时，所有“用户”都表现得过于理性、礼貌或遵循常规逻辑，无法测试产品的极端边缘情况。
    *   **应用**：在模拟用户对话时，使用 VS 生成“用户行为分布”（例如：5 种可能的投诉理由及其发生概率），而非直接生成一条对话。
    *   **价值**：还原真实世界中用户行为的多样性（包括非理性、情绪化行为），提升下游 Agent 的鲁棒性。

3.  **合成数据工厂（Data-Centric AI）**
    *   **痛点**：用 LLM 生成训练数据（如数学题、代码题）时，数据分布过于集中，导致微调后的模型在特定题型上过拟合，泛化能力差。
    *   **应用**：让模型生成“题目类型分布”和“解题思路分布”，而非直接生成题目。要求模型显式规划“这道题属于难/中/易的比例”以及“涉及知识点的多样性”。
    *   **价值**：如论文所示，可显著提升下游模型在 MATH500 等基准上的准确率（+3-4%），且无需额外训练成本。

4.  **决策辅助与风险推演（商业分析/医疗咨询）**
    *   **痛点**：AI 给出的建议往往只有一种“标准最优解”，忽略了现实中的不确定性或多路径可能性。
    *   **应用**：在咨询场景中，要求模型输出“未来 3 种可能的发展路径及其概率权重”，并解释为何某些低概率路径值得考虑。
    *   **价值**：将 AI 从“独断的专家”转变为“概率思维的顾问”，帮助用户看到被典型性偏差掩盖的潜在风险或机会。

## 可立刻试的小实验

### 实验 1：打破“讲笑话”的平庸魔咒
*   **输入提示 (Direct)**: "讲一个关于程序员的笑话。"
*   **输入提示 (VS)**: "请列出 5 个关于程序员的笑话。对于每个笑话，请评估它在程序员群体中的‘好笑程度’（0.0-1.0）和‘新颖程度’（0.0-1.0）。请确保这 5 个笑话在风格上（如：冷笑话、双关语、讽刺）有显著差异，不要只选最经典的那个。"
*   **步骤**:
    1.  分别用两种提示调用同一个经过 RLHF 对齐的模型（如 Llama-3-8B-Instruct 或 Qwen-Max）。
    2.  重复运行 5 次，收集所有输出。
    3.  计算语义相似度（使用 Sentence-BERT 计算余弦相似度矩阵）。
*   **期望输出**:
    *   Direct 模式：5 次运行可能重复出现 2-3 个经典笑话（如"Hello World"相关），语义相似度极高（>0.8）。
    *   VS 模式：5 个笑话风格迥异，涵盖不同梗，语义相似度显著降低（<0.5），且包含一些“非典型”但合理的幽默。

### 实验 2：合成数学题的多样性与下游增益
*   **输入提示 (Direct)**: "生成 10 道关于分数的数学应用题，难度适中。"
*   **输入提示 (VS)**: "生成 10 道关于分数的数学应用题。首先，规划这 10 道题的知识点分布（例如：3 道纯计算，4 道混合运算，3 道生活应用），并给出每道题的预估难度系数。然后生成题目。确保题目情境不重复（避免全是买水果）。"
*   **步骤**:
    1.  生成两组数据集（Direct 组 vs VS 组）。
    2.  使用这两组数据分别微调一个小型基座模型（如 Qwen-1.5-1.8B）。
    3.  在 MATH500 或类似的简单数学测试集上评估微调后模型的表现。
*   **期望输出**:
    *   Direct 组数据：题目情境高度重复（大量“买苹果/香蕉”），模型微调后在变式题上表现一般。
    *   VS 组数据：情境丰富（工程、旅行、分配等），微调后模型在测试集准确率提升，泛化性更好。

### 实验 3：概率调节控制“疯狂”程度
*   **输入提示**: "生成 5 个关于‘未来城市’的科幻设定。"
*   **变体 A (高典型性)**: "生成 5 个设定，每个设定的发生概率必须 > 0.6。"
*   **变体 B (高多样性)**: "生成 5 个设定，每个设定的发生概率必须 < 0.3（即低概率但合理），并解释为什么它们虽然概率低但逻辑自洽。"
*   **步骤**:
    1.  运行上述两个变体。
    2.  人工评估设定的“脑洞”大小和“逻辑合理性”。
*   **期望输出**:
    *   变体 A：设定类似《赛博朋克 2077》或《银翼杀手》的常见变体，安全但无聊。
    *   变体 B：出现类似“城市建立在巨型真菌上”或“人类通过梦境共享算力”等反直觉设定，但模型能自圆其说，成功探索了低概率空间。

## 产品 / Agent 灵感

1.  **“创意发散器”插件**
    *   **功能**：作为写作助手或头脑风暴工具的后端。用户输入主题，插件自动在后台运行 VS 策略，生成 5-10 个不同维度的方案及概率评估，最后只向用户展示“概率适中但新颖度最高”的 3 个选项。
    *   **卖点**：解决"AI 写东西太像 AI"的痛点，提供人类编辑级别的多样性。

2.  **动态对话模拟器 (Dynamic Roleplay Engine)**
    *   **功能**：用于游戏 NPC 或客服培训。不再让 NPC 直接回复，而是让 NPC 先“思考”：“如果我是这个角色，我有 30% 概率愤怒，40% 概率困惑，30% 概率讲道理”，然后基于这个分布生成回复。
    *   **卖点**：让虚拟角色拥有“不可预测性”和“真实人性”，避免对话陷入死循环。

3.  **数据增强流水线 (Data Augmentation Pipeline)**
    *   **功能**：针对数据匮乏的垂直领域（如医疗、法律），自动构建“分布感知”的数据生成器。在生成训练数据前，先让 LLM 规划数据分布的熵，强制覆盖长尾案例。
    *   **卖点**：用低成本（推理时）替代昂贵的数据标注，直接提升小模型微调效果。

## 跟现有系统怎么接

1.  **API 层改造 (Prompt Wrapper)**
    *   不需要重新训练模型。在现有的 LLM 调用层（如 LangChain, LlamaIndex）中间插入一个 `VerbalizedSampler` 类。
    *   **逻辑**：拦截用户 Prompt -> 注入 VS 模板（包含 $k$ 个候选和概率要求） -> 调用 LLM -> 解析输出（提取 JSON 格式的 `{text: str, prob: float}` 列表） -> 根据业务逻辑（如取 Top-1 或随机采样）返回结果。

2.  **后处理解析器 (Parser)**
    *   由于模型输出的概率可能是幻觉（不守恒），需要编写一个轻量级解析器：
        *   提取所有候选项。
        *   对概率进行归一化（Softmax 或简单归一化），确保 $\sum p = 1$。
        *   如果模型未输出概率，默认均匀分布或根据文本长度/复杂度估算。

3.  **与解码策略正交组合**
    *   VS 可以与现有的 `Temperature`、`Top_P` 组合使用。
    *   **建议配置**：VS 负责宏观多样性（不同思路），`Temperature` 负责微观多样性（措辞变化）。设置 `Temperature=0.7` 配合 `VS (k=5)` 效果通常最佳。

## 风险与坑

1.  **概率幻觉 (Probability Hallucination)**
    *   **风险**：模型输出的概率数字是编造的，不代表真实的置信度。如果业务逻辑依赖这些概率做决策（如“只选概率>0.8 的”），可能会失效。
    *   **对策**：将概率视为“相对新颖度”或“风格标签”的代理，而非严格的数学概率。或者在解析后引入一个轻量级 Reward Model 对候选项进行二次打分校准。

2.  **Token 成本与延迟**
    *   **风险**：生成 $k$ 个候选及其概率，Token 消耗量是生成单个回答的 $k$ 倍。对于实时性要求高的场景（如即时聊天），延迟可能增加 3-5 倍。
    *   **对策**：仅在“创意生成”、“数据合成”等非实时场景使用 VS。实时对话可改为“异步生成”或仅生成 Top-2 候选。

3.  **小模型能力不足**
    *   **风险**：参数量较小（<7B）或未经过充分指令微调的模型，可能无法理解“生成分布”的指令，导致输出乱码或无法解析概率。
    *   **对策**：对模型规模设限（建议 13B+ 或 GPT-4 级别），或针对小模型设计简化的 VS 模板（如只要求列出 3 个不同角度的观点，不强制要求概率数值）。

4.  **格式解析失败**
    *   **风险**：模型可能不严格遵守 JSON 格式，导致解析器报错。
    *   **对策**：使用 Few-Shot 示例在 Prompt 中严格规定输出格式，并配合 `json_mode` 或结构化输出工具（如 Pydantic 验证）。

## 跟进清单

- [ ] **Prompt 模板库构建**：针对写作、对话、数学、代码四个核心场景，设计标准的 VS 提示词模板（包含 $k$ 值调节接口）。
- [ ] **解析器开发**：编写一个鲁棒的 Python 解析器，能处理模型输出的非标准概率格式，并实现归一化逻辑。
- [ ] **基准测试 (Benchmark)**：在本地部署一个开源模型（如 Qwen-7B-Chat），复现论文中的“创意写作多样性”和“数学题合成”实验，验证提升幅度。
- [ ] **成本评估**：计算在典型业务场景下，引入 VS 后的 Token 成本增量与多样性收益的 ROI。
- [ ] **用户反馈收集**：在小范围产品中上线“创意模式”（基于 VS），收集用户对“多样性”和“质量”的主观评分。
