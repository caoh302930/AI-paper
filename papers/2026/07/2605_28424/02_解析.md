# Skill0.5: Joint Skill Internalization and Utilization for Out-of-Distribution Generalization in Agentic Reinforcement Learning

**Authors:** Jiapeng Zhu, Jianxiang Yu, Yibo Zhao, Chengcheng Han, Qi Gu, Xunliang Cai, Xiang Li, Weining Qian

## TL;DR and contributions
这篇论文提出了一种名为 **Skill0.5** 的强化学习框架，旨在解决智能体（Agent）在面对未知任务（OOD）时，如何处理“技能”的难题。核心思想是**差异化对待技能**：将通用的、基础性的推理技能“内化”进模型参数中，而将随任务变化的具体执行技能保留在提示词（Prompt）中动态调用。通过一个“难度感知路由器”，系统根据任务掌握程度动态调整训练策略，既避免了上下文过长导致的推理退化，又防止了全内化导致的知识冲突。

**Main contributions:**
- 提出技能差异化处理范式：通用技能内化（General Internalization）+ 任务技能外置（Specific Utilization）。
- 设计难度感知路由器（Difficulty-Aware Router），将任务动态分为难、中、易三类，分别采用特权蒸馏、标准强化学习、反事实利用检查三种优化策略。
- 在 ALFWorld 和 WebShop 的 OOD 设置下，相比最强基线（SkillRL）提升了显著的泛化能力（ALFWorld OOD +8.5%）。

**Compared against:** Zero-shot, Few-shot, ReAct, Reflexion, Mem0, ExpeL, RLOO, GRPO, SkillRL, SKILL0, SLIM.
**On datasets:** ALFWorld (Embodied tasks), WebShop (Shopping tasks).
**Headline improvements:** 在 ALFWorld OOD 设置下，相比 SkillRL 提升 **+8.5%** (从 45.3% 到 58.5%)；在 WebShop OOD 下提升 **+3.9%**。

## What matters, what doesn't

- **🎯 Core idea (read carefully):** 技能必须分两类处理：通用技能（如“先思考再行动”）要学进脑子里（参数），具体技能（如“如何加热土豆”）要查表（Prompt）。这是解决 OOD 泛化的关键。
- **🔧 Useful in practice:** 难度感知路由器的实现逻辑（基于通过率动态划分 Hard/Medium/Easy），以及针对 Easy 任务的“反事实检查”（Anti-Shortcut）机制，这对防止模型“走捷径”非常有效。
- **📎 Nice to know:** 具体的数学公式推导（如 JSD 损失函数的细节），以及 WebShop 数据集的具体划分统计（Appendix B）。
- **⚠️ Deprecated / superseded:** 传统的“全外置”（Full Externalization，如 SkillRL）和“全内化”（Full Internalization，如 SKILL0）策略在 OOD 场景下已被证明存在明显缺陷（上下文干扰或知识冲突）。
- **🔕 Skippable:** 标准的基线方法介绍（Related Work 中罗列的旧方法细节），以及超参数设置的详细表格（除非你要复现）。

## Context and prerequisites

要理解这篇论文，首先需要明白大模型智能体（LLM Agent）在解决复杂任务时面临的“技能困境”。现有的方法通常走两个极端：要么把所有技能都写在 Prompt 里（全外置），要么把所有技能都训练进模型参数里（全内化）。

**全外置**的问题在于“上下文过载”。想象一下，如果每次解题都要把一本厚厚的教科书（通用技能）和一本具体的习题集（任务技能）都塞进 Prompt 里，模型的注意力会被稀释，导致推理能力下降，尤其是在长任务中，模型容易“迷失在中间”（Lost in the Middle）。

**全内化**的问题在于“僵化与冲突”。如果把所有技能都学进参数里，模型就失去了灵活性。当遇到一个全新的任务（OOD），模型内部已经固化的旧知识（比如“冰箱是用来冷却的”）可能会与新任务的具体指令（比如“把热土豆放进冰箱”）发生冲突，导致模型产生幻觉或执行错误。

这篇论文的核心洞察是：**技能是有层次的**。有些技能是通用的认知基础（如“遇到问题先规划”），这些应该内化，成为模型的“本能”；而有些技能是具体的操作规则（如“在这个游戏中，按 A 键可以跳跃”），这些应该保留在外部，作为动态的“说明书”。Skill0.5 正是为了解决这种混合需求而设计的。

## Method

### The big picture (layman version)
Skill0.5 就像一个聪明的教练，它不会用一种方法教所有学生。它首先观察每个学生的表现（任务难度），然后采取不同的教学策略：
1.  **对于完全不会的“难题”学生**：教练会手把手教，把通用的解题思路（通用技能）直接灌输给学生，让学生把这种思路刻在脑子里（内化），哪怕现在还没学会具体操作，也要先学会“怎么思考”。
2.  **对于“中等”学生**：教练让他们自己多练几次，通过试错来巩固技能，争取把任务做对（标准强化学习）。
3.  **对于“简单”学生**：教练会故意把“说明书”拿走，看学生是不是真的学会了，还是只是在死记硬背答案。如果学生没说明书就不会做题，说明他真正利用了技能；如果没说明书也能做对，说明他在“走捷径”，教练就会惩罚这种行为，强迫他必须参考说明书（反事实检查）。

通过这种动态的、分层的训练，模型既拥有了通用的推理本能，又保持了灵活调用新技能的能力，从而在面对从未见过的新任务时也能表现出色。

### The walkthrough

Skill0.5 的训练过程分为两个阶段，核心在于**动态路由**和**分层优化**。

**第一阶段：难度感知路由 (Difficulty-Aware Routing)**
在训练开始时，模型还不知道哪些任务难、哪些容易。系统会先让模型用“标准提示词”（只包含检索到的具体任务技能，不包含通用技能）尝试解决一批任务。
- 我们计算每个任务 $x_i$ 的**经验通过率** $p_i$。
- 设定一个动态阈值 $\eta_t$（基于过去几个 batch 的平均通过率滑动窗口计算）。
- **路由逻辑**：
  - 如果 $p_i = 0$（完全失败），归类为 **Hard** 任务。
  - 如果 $0 \lt p_i \le \eta_t$，归类为 **Medium** 任务。
  - 如果 $p_i \gt \eta_t$，归类为 **Easy** 任务。

**第二阶段：分层优化 (Tier-Tailored Optimization)**
根据路由结果，对不同类型的任务应用不同的损失函数：

1.  **Hard Tasks: 特权蒸馏 (Privileged Distillation)**
    - **动机**：模型连基础逻辑都没有，直接强化学习梯度为零（因为全失败了）。我们需要先教它“怎么思考”。
    - **操作**：给模型一个“特权提示词”（Privileged Prompt），里面包含**通用技能** $\mathcal{S}_G$ 和具体技能。让模型在这个“开卷考试”环境下重新尝试，收集成功的轨迹。
    - **目标**：用这些成功的轨迹作为“老师”，通过**Jensen-Shannon Divergence (JSD)** 损失函数，强制模型在“不开卷”（只给具体技能）的情况下，模仿老师的推理步骤。
    - **公式**：$\mathcal{L}_{\text{hard}} = \frac{1}{|\mathcal{T}|} \sum \text{JSD}(\text{sg}[\pi_{\theta}^{\text{t}}] \parallel \pi_{\theta}^{\text{s}})$。这里 $\pi^{\text{t}}$ 是老师（有通用技能），$\pi^{\text{s}}$ 是学生（无通用技能），sg 表示停止梯度，只更新学生。
    - **效果**：将通用技能的逻辑内化到参数中。

2.  **Medium Tasks: 能力强化 (Capability Reinforcement)**
    - **动机**：模型能偶尔做对，但不够稳定。
    - **操作**：直接使用第一阶段收集的轨迹，应用标准的 **GRPO** (Group Relative Policy Optimization) 算法。
    - **目标**：最大化成功率。利用组内归一化的优势函数 $A_i^{(g)}$ 来更新策略。
    - **公式**：$\mathcal{L}_{\text{medium}}$ 是标准的 PPO/GRPO 形式，通过裁剪（clip）防止策略更新过大。

3.  **Easy Tasks: 反事实利用检查 (Anti-Shortcut Utilization)**
    - **动机**：模型太容易做对，可能是在“走捷径”（比如死记硬背任务指令直接输出动作，根本没看技能提示词）。这在 OOD 场景下是致命的。
    - **操作**：引入**反事实探针**。对 Easy 任务，故意**移除**所有具体技能提示词（$c_t^{\text{none}} = \emptyset$），让模型再次尝试。
    - **计算利用增益**：$u_i = p_i - p_i^{\text{none}}$。$p_i$ 是有技能时的通过率，$p_i^{\text{none}}$ 是无技能时的通过率。如果 $u_i$ 很小或为负，说明模型根本没用到技能。
    - **目标**：构造一个**利用优势** $A_i^u$，如果 $u_i$ 低于平均水平，就给予负奖励，惩罚那些不依赖技能的行为。
    - **公式**：$\hat{A}_i^{(g)} = A_i^{(g)} + A_i^u$。将利用优势加到标准优势上，共同指导 GRPO 更新。

**总目标**：$\mathcal{L} = \mathcal{L}_{\text{hard}} + \mathcal{L}_{\text{medium}} + \mathcal{L}_{\text{easy}}$。

## Challenges in the field — and what this work addresses

1.  **上下文干扰 vs. 知识冲突的权衡**
    - **难点**：全外置导致 Prompt 太长，模型注意力分散（Contextual Interference）；全内化导致模型无法适应新指令，产生知识冲突（Parametric Knowledge Conflict）。
    - **Skill0.5 的解法**：通过**解耦**技能类型。通用技能（长、稳定）内化，解决上下文干扰；具体技能（短、多变）外置，解决知识冲突。这种混合架构在推理时既保持了轻量级 Prompt，又保留了灵活性。

2.  **训练过程中的“走捷径”现象 (Shortcut Learning)**
    - **难点**：在强化学习中，一旦模型找到一种不需要真正理解技能就能得分的方法（例如 memorizing input-output pairs），它就会停止学习真正的技能利用能力。这在 OOD 测试时会导致性能崩塌。
    - **Skill0.5 的解法**：针对 Easy 任务设计**反事实检查**。通过强制移除技能提示词来测量“技能增益”，如果增益低就惩罚。这迫使模型必须真正依赖外部技能才能得分，从而在 OOD 场景下保持鲁棒性。

3.  **困难任务上的梯度消失**
    - **难点**：对于完全不会的 Hard 任务，模型尝试多次都失败，奖励为 0，导致梯度消失，无法开始学习。
    - **Skill0.5 的解法**：引入**特权蒸馏**。利用包含通用技能的“特权”环境生成成功轨迹，作为监督信号（Teacher），为模型提供初始的梯度方向，打破冷启动僵局。

**未解决的问题**：该方法目前主要验证于文本交互环境（ALFWorld, WebShop），对于多模态环境或超长视野（Long-horizon）任务中的技能内化效率，以及通用技能与具体技能边界的自动划分，仍需进一步探索。

## Experiments and results

实验在 **ALFWorld** 和 **WebShop** 两个基准上进行，严格区分了 ID（训练分布）和 OOD（未见过的分布）设置。

- **主要结果**：
  - **ALFWorld**: Skill0.5 在 ID 设置下达到 **93.1%** 成功率（SOTA），在 OOD 设置下达到 **58.5%**。相比最强的基线 SkillRL，ID 提升 +2.3%，OOD 提升 **+13.2%** (从 45.3% 到 58.5%)。
  - **WebShop**: 在 ID 和 OOD 设置下均取得最佳性能，OOD 平均提升 **+3.9%**。
  
- **消融实验 (Ablation Study)**：
  - **Internalize-Only** (只内化，不检查利用)：OOD 性能从 58.5% 降至 52.8%。证明“反事实检查”对于 OOD 泛化至关重要。
  - **Utilize-Only** (只检查利用，不内化)：ID 和 OOD 性能均大幅下降（ID 85.1%, OOD 50.9%）。证明“内化通用技能”是基础能力的前提，没有基础能力，利用检查无从谈起。

- **案例分析 (Case Study)**：
  - **SkillRL (全外置)**：在 OOD 任务中，通用技能的长上下文干扰了具体指令，导致模型执行了错误的“冷却”操作（Contextual Interference）。
  - **SKILL0 (全内化)**：模型内部固化了旧任务的“拿起 - 放置”模板，即使看到了新指令“打开台灯”，也强行执行旧模板，导致参数冲突（Parametric Conflict）。
  - **SLIM**：过早退出了通用技能，导致模型在训练后期出现行为崩塌（Behavioral Collapse），产生幻觉。
  - **Skill0.5**：成功内化了通用推理，同时忠实执行了新技能，在所有案例中均获胜。

## Code highlights

**Status:** *Inferred from paper* (Repo exists: https://github.com/JasonZhujp/Skill0_5，但无法直接读取源码细节，基于论文描述推断)。

- **Repo Structure**: 预计包含 `train.py` (主训练循环), `router.py` (难度路由逻辑), `loss.py` (包含 JSD 和反事实损失), `envs/` (ALFWorld/WebShop 封装)。
- **Key Implementation Details**:
  - **Router**: 使用滑动窗口计算动态阈值 $\eta_t$，需维护一个历史通过率队列。
  - **Distillation**: 在 Hard 任务中，需实现“特权提示词”生成逻辑，并计算 Token 级别的 JSD 损失（仅针对 Top-64 tokens）。
  - **Counterfactual Probe**: 在 Easy 任务中，需额外采样一组 $c_t^{\text{none}}$ 的轨迹，计算 $p_i^{\text{none}}$ 并动态调整 Advantage。
  - **Hyperparameters**: 使用 Qwen2.5-7B，GRPO 组大小 $G=8$，学习率 $1e-6$。

## Open questions and limitations

1.  **通用技能与具体技能的边界**：论文假设技能库已经明确分为 General 和 Specific。在实际应用中，如何自动识别一个技能是通用的还是具体的？这可能需要额外的元学习或人工标注。
2.  **计算开销**：虽然推理时只保留具体技能，但在训练阶段，Hard 任务需要额外的特权采样，Easy 任务需要额外的反事实采样，这增加了训练时的计算成本（约 2-3 倍采样量）。
3.  **OOD 技能的检索质量**：该方法依赖于具体技能的检索（Top-K）。如果检索到的技能本身是错误的或不相关的，反事实检查可能会惩罚模型，或者模型无法利用错误的技能。
