# 可以做什么：基于 SciNet 的科研 Agent 实战发散

## 可迁移到的场景（≥4）

1.  **专利布局与规避设计（IP Strategy）**
    *   **痛点：** 现有专利检索只能找到“技术点相似”的专利，无法识别“核心基础专利”（颠覆性）或“技术绕道路径”。
    *   **迁移：** 将 SciNet 的 `Disruption Index` 迁移为“专利阻断指数”，将 `Path-wise` 任务迁移为“技术规避路径规划”。
    *   **价值：** 帮助企业识别哪些专利是必须绕开的“路障”，哪些是尚未被封锁的“蓝海”技术路径。

2.  **学术基金评审与选题辅助（Grant & Topic Selection）**
    *   **痛点：** 评审专家难以快速判断一个选题是“修修补补”还是“范式转移”。
    *   **迁移：** 利用 `Ego-centric` 任务评估待申报项目的“新颖性潜力”。不只看关键词热度，而是计算该项目在引用网络中可能产生的“结构洞”或“颠覆性”。
    *   **价值：** 为基金委提供“颠覆性指数”评分，辅助筛选高风险高回报项目；为研究者提供“选题避坑”报告（避免进入已饱和的巩固型路径）。

3.  **企业研发情报雷达（R&D Intelligence）**
    *   **痛点：** 竞品分析往往停留在“对方发布了什么”，无法理解“对方技术路线的演变逻辑”。
    *   **迁移：** 构建竞品技术演化图谱（`Path-wise`）。输入竞品 A 的早期核心专利，输出其最新的技术节点，并自动识别中间的关键转折点（如：从“路线 X"转向“路线 Y"的决策论文）。
    *   **价值：** 预测竞品下一步技术方向，识别其技术路线中的“断裂点”（即其技术可能失效的环节）。

4.  **跨学科交叉创新发现（Cross-Disciplinary Innovation）**
    *   **痛点：** 跨学科创新往往发生在两个看似无关领域的“隐性连接”处，传统检索无法发现。
    *   **迁移：** 利用 `Pair-wise` 中的“共提及”和“情感分析”逻辑，但将范围扩大到不同学科子领域。寻找“领域 A 的方法”被“领域 B 的论文”以“支持/改进”情感引用的案例。
    *   **价值：** 自动生成“技术迁移机会清单”，例如：“材料科学中的 X 方法在生物医学中被 Y 论文以‘颠覆性’方式引用，建议尝试迁移”。

## 可立刻试的小实验（≥3）

### 实验 1：颠覆性论文“盲测”
*   **输入：** 选定一个细分领域（如"Diffusion Models"），列出该领域近 3 年 Top 10 高引论文。
*   **步骤：**
    1.  使用当前主流科研 Agent（如 Perplexity, Elicit, 或本地部署的 RAG 系统），提问：“请列出该领域最具颠覆性的 5 篇论文，并说明理由。”
    2.  手动计算这 5 篇论文的 **Disruption Index**（可用 OpenAlex API 获取引用数据，套用公式 $D = (N_i - N_j) / (N_i + N_j)$）。
    3.  对比 Agent 列出的论文与真实 Top 5 颠覆性论文的重合度。
*   **期望输出：** 验证重合度是否低于 20%（预期结果：Agent 倾向于列出“高引用”但非“颠覆性”的论文，如综述或巩固型论文）。

### 实验 2：技术演化路径“断链”测试
*   **输入：** 一对经典论文（起点）和最新 SOTA 论文（终点），例如：`ResNet (2015)` -> `Swin Transformer (2021)`。
*   **步骤：**
    1.  询问 Agent：“请列出从 ResNet 到 Swin Transformer 的关键技术演化路径（列出 3-5 篇中间里程碑论文）。”
    2.  人工构建一条基于引用图 BFS 的最短/最强路径作为 Ground Truth。
    3.  检查 Agent 生成的路径中，相邻两篇论文之间是否存在**直接引用**或**明确的逻辑递进关系**（而非仅语义相似）。
*   **期望输出：** 发现 Agent 生成的路径中至少有一处“逻辑跳跃”（即论文 A 和论文 B 之间没有直接引用关系，Agent 强行拼接），验证 `Connectivity` 指标的低分原因。

### 实验 3：引用情感“误判”压力测试
*   **输入：** 选取 10 对存在“反驳”或“批评”关系的论文对（可通过 Google Scholar 评论或 Twitter 学术圈讨论挖掘，如某论文被后续论文指出“实验不可复现”）。
*   **步骤：**
    1.  将论文对及引用上下文（Citation Context）输入 Agent。
    2.  提问：“论文 B 对论文 A 的态度是支持、中立还是反对？请引用原文依据。”
    3.  统计 Agent 将“反对”误判为“支持”或“中立”的比例。
*   **期望输出：** 验证 `Cite-Sentiment` 准确率是否低于 20%，特别是当反驳语气委婉（如“虽然...但是..."）时。

## 产品 / Agent 灵感

1.  **“科研导航仪”插件 (SciNet Navigator)**
    *   **功能：** 浏览器插件，悬浮在 arXiv/Google Scholar 页面上。
    *   **核心逻辑：** 不显示“相关论文”，而是显示“关系图谱”。
    *   **UI 亮点：**
        *   **颠覆性雷达：** 用红/绿高亮显示该论文是“颠覆者”还是“加固者”。
        *   **路径回溯：** 点击“演化路径”，自动生成从该论文到当前 SOTA 的因果链条，而非简单的引用列表。
        *   **情感地图：** 在引用列表中，用不同颜色标记“支持”、“反驳”、“扩展”关系。

2.  **自动文献综述生成器 (Deep Reviewer)**
    *   **痛点解决：** 现有综述生成器只是“拼凑摘要”。
    *   **创新点：** 基于 `Path-wise` 逻辑，强制 Agent 按“技术演化时间线”组织内容，而非按“主题”组织。
    *   **输出结构：** “问题起源 (A) -> 第一次尝试 (B, 被 C 反驳) -> 关键转折 (D) -> 当前方案 (E)"。
    *   **差异化：** 每一段结论都附带“关系证据链”（引用了哪篇论文反驳了上一代方案）。

3.  **科研选题“避坑”助手**
    *   **功能：** 输入一个拟定的研究 Idea。
    *   **分析：** 扫描该 Idea 在引用网络中的位置。
    *   **预警：** “该方向已有 80% 的论文属于‘巩固型’研究，且 3 篇高引论文已证明该路径存在理论瓶颈（引用反驳关系）。”
    *   **建议：** “建议转向 X 领域，存在未开发的‘颠覆性’连接点。”

## 跟现有系统怎么接

1.  **数据层接入 (Data Layer)**
    *   **OpenAlex API：** 必须接入 OpenAlex 全量数据（2.69 亿篇），这是计算 `Disruption Index` 和构建引用图的基础。
    *   **GROBID 服务：** 部署 GROBID 解析 PDF，提取 `Citation Context`（引用上下文），这是判断 `Pair-wise` 情感的关键。
    *   **图数据库：** 使用 Neo4j 或 NetworkX 存储引用关系，预计算 BFS 路径，避免实时计算超时。

2.  **检索层改造 (Retrieval Layer)**
    *   **混合检索策略：** 放弃纯 Vector Search。采用 `Keyword + Embedding + Graph-Traversal` 混合模式。
    *   **重排序 (Rerank)：** 在 Rerank 阶段引入 `SciNet` 的特征：
        *   如果用户问“最新进展”，提升 `Novelty` 高的论文权重。
        *   如果用户问“技术路线”，提升 `Path-Connectivity` 高的论文权重。

3.  **Agent 逻辑层 (Agent Logic)**
    *   **工具调用 (Tool Use)：** 为 Agent 增加 `get_disruption_score(paper_id)` 和 `find_path(start_paper, end_paper)` 两个专用工具。
    *   **思维链 (CoT) 增强：** 在 Prompt 中强制要求 Agent 在生成综述前，先输出“关系推理步骤”（例如：先确认 A 是否反驳 B，再确认 C 是否改进 A）。

## 风险与坑

1.  **数据滞后与马太效应**
    *   **风险：** 基于引用数的指标（如 BFS 选最高引用路径）天然偏向“热门”路径，可能忽略“冷门但正确”的早期路径。
    *   **对策：** 在计算路径时，引入“时间衰减”因子，或结合语义相似度对 BFS 结果进行二次筛选，避免只走“大路”。

2.  **隐性关系无法捕捉**
    *   **风险：** 很多科学影响是“未引用”的（Parallel Discovery）。SciNet 基于显式引用，会漏掉这部分。
    *   **对策：** 明确告知用户系统的局限性，并在 UI 中标注“基于显式引用网络”，同时保留语义检索作为补充。

3.  **计算成本高昂**
    *   **风险：** 对 2.69 亿篇论文进行实时的 BFS 和指标计算是算力黑洞。
    *   **对策：** **预计算 (Pre-computation)** 是关键。离线计算好所有子领域的 Top 路径和颠覆性评分，存入向量库或图数据库，Agent 只负责查询和组装。

4.  **领域适应性差**
    *   **风险：** 生物/医学的引用模式与 CS/物理不同（如医学综述引用多，CS 会议引用多）。
    *   **对策：** 按 `Sub-field`（2640 个子领域）分别构建索引和参数，避免“一刀切”。
